# Windows project-consent compatibility

Continuation of integrated Windows commit `22be8ab836578256abb8dd480e0cf22c71ed4f02`, November 2, 2026. Parent portable validation now covers the integrated `/2` and v4 changes. No native Windows execution or paid voice creation is claimed.

## Record and service API

- `VoiceConsentMethod` distinguishes `RecordedStatement` and `ProjectAttestation`; serialized values match Mac `recordedStatement` and `projectAttestation`.
- `VoiceProjectConsent.Text` is the fixed checkbox statement. `ConsentText` serializes as `text`. The language is `en` or `et`; the only filename is `reference.wav`.
- `VoiceConsentRecord.Statement` is nullable; `ProjectConsent` is appended as an optional constructor argument. `Language`, `ReferenceAudioFile`, `ReferenceAudioSha256` and `ConsentMethod` are computed and excluded from JSON. `/1` retains `statement` without new evidence properties; `/2` emits only `projectConsent`.
- `SaveReferenceAudio` and `ReferenceAudio` use the same protected private writes, bounded reads, symlink checks and hash verification as the legacy statement. `Statement` remains strictly the legacy accessor. Existing `DiscardStatement` cleanup intentionally removes both evidence filenames, including abandonment and recovery failure.
- `EnrollmentQuote.Prepare(create, request, consent, attestations)` and its corresponding `Validate` overload bind the project evidence. `Verify` is absent. Nullable serialized `ConsentMethod` is omitted for legacy quotes; `Method` supplies the legacy default without altering their fingerprints.
- `PrepareProjectPlanAsync` uses every sample's calibrated whole/part embeddings, establishes the owner from the first accepted project sample, drops failed spans and refuses fewer than 30 seconds retained. `RecoverPlanAsync` supports both records; `VoiceEnrollmentPlan.IsRecovery` is distinct from `VerificationPassed`. Project plans never claim statement verification. A project plan's creator is bound during preparation and rechecked before dispatch; recovery also checks the on-disk journal's complete `SnapshotFingerprint` before approval.
- `OwnVoicePolicy.ConsentMethod` is included in project request/review fingerprints, while legacy hashes remain byte-compatible. Private permits, currentness, one-use approval, account/region checks, durable operation intent and provider verification status are not bypassed. The actual multipart body names project files `sample-01.wav` onward and describes checkbox evidence and its reference hash; no statement file or Scribe request is invented.

Private recovery quote fingerprints and journals remain platform-local: .NET and Swift already have different local timestamp/fingerprint representations. Shared consent metadata, exact evidence text, reference/sample hashes, status, creator and duration semantics match; moving an executable recovery authorization between platforms is not claimed or supported.

## Generated-speech QA

`VoiceLabTakeQaFailure.InsufficientGeneratedSpeech` serializes to `insufficientGeneratedSpeech`. `VoiceInsufficientGeneratedSpeechException` is the typed support refusal. `VoiceSpeakerCheck.GeneratedEmbeddingAsync` requires real 24 kHz generated input and three seconds before canonical resampling/VAD. The existing ONNX window path checks the actual selected 16 kHz samples through `SpeakerAudio.GeneratedWindows`; fewer than 48,000 yields that refusal, without padding or source borrowing. Nonfinite input is not classified as insufficient speech.

`VoiceLabTakeQaResult` measurements are nullable. An insufficient-support row retains its paid synthesis receipt/audio but has no fabricated transcript/speaker/loudness/peak measurement and no Scribe QA charge. A missing-measurement row cannot pass even with an empty failure list. Recipe creation separately requires all measured values. Measured low similarity continues to fail as `Speaker` with the actual score and QA evidence.
