# VoxClip architecture

Status: normative for 0.1.0 (milestone M1). Date: 2026-10-25.

This document fixes the repository layout, the module boundaries, the data flow from import to export, the concurrency model on each platform, both media pipelines, the headless CLI, caching, error handling, logging and update checks. The locked product decisions are listed in [decisions.md](decisions.md). The visual and interaction design is in [design.md](design.md). Releases are in [release.md](release.md) and publishing in [publishing.md](publishing.md).

The words **must**, **must not**, **should** and **may** are used in their RFC 2119 sense. Constants in this document are part of the contract. If an implementation needs a different value, change this document in the same commit.

Provenance: the research reports in the VoxClip planning workspace (`native-video.md`, `ss-mac.md`, `ss-win.md`, `vox-editing.md`, `vox-captions.md`, `local-models.md`, `vox-integration.md`). Implementers do not need to read them.

Rules:

- `shared/` is the source of truth. Neither app may keep its own copy of a style, prompt, schema, font, token or fixture. Generated platform files (`Tokens.swift`, `Tokens.xaml`) are committed, carry a `GENERATED - do not edit` header, and are re-generated by `tools/design`; CI fails if they drift (section 12).
- Each `shared/` subfolder has a `README.md` written by the spec that owns it (captions, editing, transcription, LLM). This document fixes only the folder names.
- `tools/` holds developer and CI tools only. Nothing in `tools/` ships.
- Release scripts live with the app they release (`apps/macos/bundle.sh`, `apps/windows/build/`). `tools/release/` holds only the cross-platform version helpers.
- No file in the repo contains a secret. Secrets are referenced by variable name and file location only (section 11.4, release.md).

## 2. Module boundaries and dependency rules

### 2.1 Layers

```text
            ┌──────────────────────────────┐   ┌──────────────────────────────┐
  UI        │ VoxClip (SwiftUI + AppKit)   │   │ VoxClip.App (WinUI 3)         │
            └──────────────┬───────────────┘   └──────────────┬───────────────┘
            ┌──────────────┴───────────────┐   ┌──────────────┴───────────────┐
  Headless  │ voxclip-cli                  │   │ VoxClip.Cli (voxclip-cli.exe) │
            └──────────────┬───────────────┘   └──────────────┬───────────────┘
            ┌──────────────┴───────────────┐   ┌──────────────┴───────────────┐
  Media     │ VoxClipMedia                 │   │ VoxClip.Media                 │
            │ AVFoundation, CoreText,      │   │ FFmpeg.AutoGen (LGPL shared), │
            │ CoreImage/Metal, Speech,     │   │ SkiaSharp 3 + HarfBuzzSharp,  │
            │ FoundationModels, whisper.cpp│   │ Whisper.net, NAudio (WASAPI)  │
            └──────────────┬───────────────┘   └──────────────┬───────────────┘
            ┌──────────────┴───────────────┐   ┌──────────────┴───────────────┐
  Core      │ VoxClipCore                  │   │ VoxClip.Core                  │
            │ Domain (pure) + Services     │   │ Domain (pure) + Services      │
            └──────────────────────────────┘   └──────────────────────────────┘
                         ▲  both read  shared/  (styles, prompts, schemas, fonts, fixtures)
```

Dependency rules (enforced by target/project references; a reverse reference is a build error by construction):

1. **Core depends on nothing but the standard library.** Swift: `Foundation` and `Synchronization` only. C#: the .NET 10 BCL only (`System.Text.Json`, `System.Net.Http`, `System.Diagnostics.Process`). No NuGet or SwiftPM dependency in Core.
2. **Core is media-free and UI-free.** Core must not import AVFoundation, CoreMedia, CoreVideo, CoreImage, CoreText, CoreGraphics, Metal, Speech, FoundationModels, Security, AppKit or SwiftUI; and must not reference FFmpeg.AutoGen, SkiaSharp, HarfBuzzSharp, Whisper.net, NAudio, WinRT or `Microsoft.UI.*`.
3. **Core has two folders with different purity:**
   - `Domain/` is pure: deterministic functions over value types, no I/O, no clocks, no randomness, no global state. Everything fixture-tested lives here: word model, normalisation and post-processing, pause and filler detection, boundary refinement over an envelope array, edit state reducer and history, `EditPlan` (cut ranges, kept ranges, time mapping, joins), clip range layer, caption text transforms, caption paging, line breaking and placement over shaped advances (shaping is an injected protocol), easing, reframe math, `finalizeClips` validation, canonical clip-response parsing, export presets and size/bitrate rules, version comparison, the log `Redactor`, and the share helpers' text rules (default caption text, the X weighted count, share URLs and their host check; publishing.md section 2) in `Domain/Publishing`.
   - `Services/` performs I/O through Foundation/BCL only, behind protocols so tests substitute fakes: project file read/write, settings store, cache index, model catalogue and downloader, HTTP connectors (ElevenLabs Scribe, Anthropic, OpenAI, xAI, Gemini, Ollama, LM Studio), CLI connectors (Claude Code `claude -p`, Codex `codex exec` / `codex app-server`) through a `ProcessRunner` protocol, GitHub release check (macOS), logging facade.
4. **Media depends on Core.** Media implements Core protocols (`Transcriber`, `GlyphShaper`, `CaptionRasterizer`, `MediaProbe`, `AudioExtractor`, `PreviewEngine`, `Exporter`, `LLMConnector` for Apple Foundation Models) with platform media and ML frameworks.
5. **UI and CLI depend on Core and Media.** The UI owns windows, views, view models, the platform secret store (Keychain / DPAPI), share helpers (pasteboard, reveal in Finder/Explorer, open URL) and the update UI. The CLI owns argument parsing and env-var key loading.
6. **Media never depends on UI.** Preview engines publish frames and time; the UI decides how to show them.
7. **Platform secret stores are UI-only.** The CLI never touches the Keychain or DPAPI (section 9.4). Core receives keys as values through a `KeyProvider` protocol and never stores them.
8. **No runtime JSON Schema engine.** Runtime validation of every shared JSON format (project files, settings, caption styles and their project patches, catalogues, prompts) is strict typed decoding in Core `Domain/`: unknown keys are rejected except under `extensions` (projects) or where the schema allows them (settings preserve unknown keys); required keys must be present, explicit `null` included; enum, pattern, range and uniqueness rules are checked in code as the schema states them. The schemas are enforced by tests instead: every fixture, every built-in style and every file the apps write in tests (project round trips, settings) is validated with a real JSON Schema 2020-12 validator that is a test-only dependency (Python `jsonschema` through `tools/schemas/validate.py` and `tools/captions/check_styles.py` in CI; a test-only NuGet such as JsonSchema.Net in `VoxClip.Core.Tests` if C# tests want it in-process). Schema `default` values that code must reproduce (CaptionStyle, captions spec 2.2) are covered by a test in both suites that loads the schema and compares each `default` with the hand-coded value.

### 2.2 Swift package (apps/macos/Package.swift)

```swift
// swift-tools-version: 6.2
import PackageDescription

let package = Package(
  name: "VoxClip",
  platforms: [.macOS(.v26)],
  products: [
    .executable(name: "VoxClip", targets: ["VoxClip"]),
    .executable(name: "voxclip-cli", targets: ["voxclip-cli"]),
  ],
  dependencies: [
    .package(url: "https://github.com/apple/swift-argument-parser", exact: "<pin at scaffold time>"),
  ],
  targets: [
    // whisper.cpp release xcframework (MIT). URL and checksum pinned at scaffold time.
    .binaryTarget(name: "whisper", url: "<whisper.cpp release xcframework zip>", checksum: "<sha256>"),
    .target(name: "VoxClipCore",
            swiftSettings: [.swiftLanguageMode(.v6)]),
    .target(name: "VoxClipMedia", dependencies: ["VoxClipCore", "whisper"],
            swiftSettings: [.swiftLanguageMode(.v6)]),
    .executableTarget(name: "VoxClip", dependencies: ["VoxClipCore", "VoxClipMedia"],
            exclude: ["Info.plist"],
            swiftSettings: [.swiftLanguageMode(.v6)],
            linkerSettings: [.unsafeFlags(["-Xlinker", "-sectcreate", "-Xlinker", "__TEXT",
                                           "-Xlinker", "__info_plist", "-Xlinker", "Sources/VoxClip/Info.plist"])]),
    .executableTarget(name: "voxclip-cli",
            dependencies: ["VoxClipCore", "VoxClipMedia",
                           .product(name: "ArgumentParser", package: "swift-argument-parser")],
            swiftSettings: [.swiftLanguageMode(.v6)],
            linkerSettings: [.unsafeFlags(["-Xlinker", "-sectcreate", "-Xlinker", "__TEXT",
                                           "-Xlinker", "__info_plist", "-Xlinker", "Sources/VoxClip/Info.plist"])]),
    .testTarget(name: "VoxClipCoreTests", dependencies: ["VoxClipCore"]),
    .testTarget(name: "VoxClipMediaTests", dependencies: ["VoxClipMedia"]),
  ]
)
```

- Swift 6 language mode with complete strict concurrency in every target. No `@preconcurrency import`, and no `nonisolated(unsafe)` or `@unchecked Sendable` without a comment that states the invariant (allowed places: section 7.1).
- No SwiftPM `resources:`. The generated `Bundle.module` accessor puts a bundle at the `.app` root, which breaks code signing. `bundle.sh` copies `shared/` assets into `Contents/Resources/shared/` (section 2.4).
- `Info.plist` is embedded into both executables with `-sectcreate` so an unbundled `swift run` binary has usage strings and `Bundle.main.infoDictionary` returns the version.
- Tests use the swift-testing framework (`import Testing`).
- `VoxClipMedia` is a refinement of the locked target list: the CLI must share the media pipeline with the app, and Core must stay media-free (decisions.md, ADR-R1).
- The SDK version written into the binary decides how macOS draws the app. Release builds pass `-Xlinker -platform_version -Xlinker macos 26.0 <SDK>` and verify it (release.md section 2.3); without it the app can lose Liquid Glass.

`InvariantGlobalization` must stay **off** (unset or `false`). In invariant mode `string.Normalize(NormalizationForm.FormC)` silently returns its input unchanged, which breaks NFC in editing 4.8, captions 3.1 and AI tighten 12.5. Culture independence comes from explicit APIs, not invariant mode: ordinal comparisons, `CultureInfo.InvariantCulture` for number formatting, `shared/caption-styles/casemap.json` for case mapping (captions 3.4), and `Rune.ToLowerInvariant` with the editing 4.7 U+0130 rule. Windows 10 1903+ ships ICU and macOS runners use the system ICU, so no extra dependency is needed. `VoxClip.Core.Tests` asserts `"o\u0303".Normalize(FormC) == "\u00F5"` so a later property change fails CI. The app reads its version from `AssemblyInformationalVersionAttribute` of the entry assembly.

### 2.4 Locating `shared/` at runtime

Both apps resolve one `SharedResources.root` directory, first match wins:

1. Env var `VOXCLIP_SHARED_DIR` (tests, CI, development).
2. macOS app or CLI inside the bundle: `<App>.app/Contents/Resources/shared/` (the CLI finds it as `../Resources/shared` relative to `Contents/MacOS/voxclip-cli`). Windows: `<AppContext.BaseDirectory>\shared\`.
3. Development fallback: walk up from the executable directory until a directory containing both `shared/caption-styles` and `apps/` is found, then use its `shared/`.
4. Otherwise fail at launch with error `sharedResourcesMissing` (section 10).

Windows copies the files at build time (fixtures excluded):

```xml
<ItemGroup>
  <Content Include="$(MSBuildThisFileDirectory)..\..\..\..\shared\**\*"
           Exclude="$(MSBuildThisFileDirectory)..\..\..\..\shared\fixtures\**"
           LinkBase="shared" CopyToOutputDirectory="PreserveNewest" />
</ItemGroup>
```

Fixtures never ship. Tests read fixtures by path from the repo (`#filePath`-relative in Swift; `VOXCLIP_SHARED_DIR` or the walk-up rule in C#).

### 2.5 Per-user data locations

| Purpose | macOS | Windows |
|---|---|---|
| Data root `<data>` | `~/Library/Application Support/VoxClip/` | `%LOCALAPPDATA%\VoxConvo\VoxClip\` |
| Settings | `<data>/settings.json` | `<data>\settings.json` |
| Models | `<data>/Models/<engine>/<modelId>/` | `<data>\Models\<engine>\<modelId>\` |
| Caches | `<data>/Cache/<contentKey>/` | `<data>\Cache\<contentKey>\` |
| Untitled-project autosave | system (DocumentGroup) | `<data>\Autosave\<projectId>.voxclip` |
| Secrets | Keychain, service `com.voxconvo.voxclip` | DPAPI files `<data>\Secrets\<account>.bin` |
| Logs | `~/Library/Logs/VoxClip/` | `<data>\Logs\` |
| Default export folder | `~/Movies/VoxClip/` | `%USERPROFILE%\Videos\VoxClip\` |
| App install | `/Applications/VoxClip.app` | `%LOCALAPPDATA%\VoxClip\` (Velopack root: `Update.exe`, `current\`) |

The Windows data root is deliberately **not** `%LOCALAPPDATA%\VoxClip\`, because Velopack owns that folder and deletes it on uninstall; models and settings must survive a reinstall.

`VOXCLIP_DATA_DIR` overrides `<data>` on both platforms (tests, CLI, CI). When it is set, logs go to `<data>/Logs/` too.

Settings are one flat JSON file with dotted keys on both platforms (schema `shared/schemas/settings.schema.json`, `"schema": "voxclip-settings/1"`; every key, type and default is listed there and design.md section 10 names the key of each row), written atomically (temp file + rename) 500 ms after the last change. Unknown keys are preserved. LLM model ids are stored **per provider** (`llm.model.anthropic`, `llm.model.openai`, …), never in one shared key.

On macOS, damaged settings are backed up before valid preferences are recovered. If persisting the recovered document fails, the store reports the load/write error but keeps that document in memory and pending for a later write. Subsequent loads and saves reuse the recovered state; write retries do not repeat recovery or create more damaged backups.

### 2.6 Project files and app instances

- **macOS.** `DocumentGroup` with a `ReferenceFileDocument` whose `readableContentTypes` and `writableContentTypes` are `[com.voxconvo.voxclip.project]` only, so a movie can never become a document's file URL. Movies are opened by replacing File > Open… (`CommandGroup(replacing: .newItem)` plus an open panel accepting projects and movies): a project goes to `NSDocumentController.shared.openDocument(withContentsOf:display:)`; a movie calls `@Environment(\.newDocument)` with `VoxClipDocument(importing: url)`. Finder and Dock opens go through an `NSApplicationDelegateAdaptor` whose `application(_:open:)` does the same split. Saving is `NSDocument` autosave-in-place (editing 10.2). Untitled projects follow the system keep/delete prompt on close.
- **Windows.** At import the project is created as `<video base name>.voxclip` in the video's folder, de-duplicated with " 2", " 3". If that folder is not writable, the project goes to `<data>\Autosave\<projectId>.voxclip` and an InfoBar says "Saved in VoxClip's folder. Use Save project as… to keep it with the video." CommandBar secondary commands add **Save project as…** (`FileSavePicker`; writes the new file with a recomputed `relativePath`, then deletes the autosave copy) and **Show project file**.
- **Windows single instance.** `VoxClip.App` defines `DISABLE_XAML_GENERATED_MAIN`. `Program.Main` runs, in order: `VelopackApp.Build().Run()`; `AppInstance.FindOrRegisterForKey("VoxClip")`; if that instance is not the current one, `RedirectActivationToAsync(AppInstance.GetCurrent().GetActivatedEventArgs())` and exit; otherwise `XamlCheckProcessRequirements()`, `ComWrappersSupport.InitializeComWrappers()` and `Application.Start(…)`. The one process keeps a map from the full project path (case-insensitive) to its window; opening an already-open project activates that window. Ctrl+N opens a new window in the same process.

## 3. Data model summary

The normative project format is defined by `doc/spec/editing.md` section 10 and `shared/schemas/project.schema.json`. The architecture relies on these properties:

- **One portable JSON file**, extension `.voxclip`, UTF-8, no BOM, identical schema on both platforms, `"format": "voxclip-project"` plus an integer `schemaVersion`. Autosaved (debounced about 1 s) with atomic writes. macOS UTType `com.voxconvo.voxclip.project` conforming to `public.json`; Windows associates `.voxclip` with `VoxClip.exe` in the Velopack install hook (current user only).
- **Source media by reference**: `absolutePath`, `relativePath` (relative to the project file's folder, null across volumes), `sizeBytes`, `contentKey` (section 8.1), plus probed duration and track facts. Resolution order and the relink confirmation ("This file looks different. Use it anyway?") are in editing spec section 10.3; if nothing resolves, show "Can't find {file}. Edits are saved." with **Locate…**.
- **Source word timings never change.** `transcript.words[]` keeps raw and refined start/end per word as produced at import. Edits never rewrite them.
- **Edits** (`EditState`, editing spec section 2.5) are a set of cut word ids, a set of cut pause ids, text corrections by word id, and an explicit **clip range layer** (`clips: [ClipRange { id, startWordId, endWordId, title?, origin: manual | ai, aiResultId?, aiClipIndex?, selected }]` plus `activeClipId`). A clip never rewrites cut flags. Segment kinds in every plan input are explicit: `word`, `pause`, `range`; no code infers a kind from an id prefix.
- **Project choices**: caption style id plus overrides and placement (`captions`), export aspect, quality, SRT and folder (`export`; sizes and bitrates are derived, section 4.1), edited share captions (`share`), cached AI runs (`ai.results`). Reframe settings arrive with M2 in a new schemaVersion.
- **Voice Lab project version 2**: `voiceLab.assets` and typed, enabled or disabled synthetic replacement segments preserve the source transcript and edit state. Core emits ordered source/synth pieces with output timing and captions for an explicit full or clip scope (Voice Lab §10; ADR-R24). The current Media compose paths accept only the old subtractive `EditPlan`; the app and CLI must reject enabled synthetic rendering until those paths consume output pieces.
- Caches and keys are never inside the project file.

## 4. Data flow from import to export

```text
 file ─► Probe ─► Project(untitled, source ref) ─► AudioExtractor ─┬─► 16 kHz mono WAV (cache)
                         │ playable at once                         └─► 10 ms RMS envelope (cache)
                         ▼
                 Transcriber (router) ─► raw engine words ─► Core post-process ─► Transcript (immutable)
                                                                             │
 user edits ─► EditState reducer ─► EditHistory (undo) ──────────────────────┤
 AI clip finder ─► canonical JSON ─► finalizeClips ─► clip candidates ─► user accepts ─► clip range layer
                                                                             ▼
                          EditPlan (Core, pure: cuts, kept sample ranges, mapTime/sourceTime, joins)
                                       │                     │
                          CaptionTrack (edited timeline)   CropTrack (M1 centre crop; M2 face-tracked)
                                       ▼                     ▼
                ┌──────────── Preview (same per-frame compose code as export) ────────────┐
                │ mac: AVPlayer + composition + FrameCompositor + fade tap                │
                │ win: audio-clocked FFmpeg engine + Skia overlay → WriteableBitmap      │
                └─────────────────────────────────────────────────────────────────────────┘
                                       ▼
                 ExportJob (full edit or clip × aspect) ─► MP4 (+ .srt) ─► share helpers (M1) / VoxConvo publish (M2)
```

Step by step:

1. **Import.** The user drops or opens a file (or a `.voxclip` project). `MediaProbe` returns duration, tracks, audio sample rate, oriented size, rotation, frame rate, codec and an HDR flag. macOS rejects `.webm`, `.mkv` and any asset whose `isPlayable` is false with `unsupportedContainer`; Windows opens them through FFmpeg. A new untitled project is created around the file, and **the video is playable immediately** (no edits yet, so the plan is the identity).
2. **Audio extraction.** One streaming pass produces the 16 kHz mono 16-bit PCM WAV used for transcription and upload (trimmed to `round(duration × 16000)` samples) and the level envelope, which is exactly editing spec 5.1 `level[]`: binary32, `frameSize = max(1, jsRound(rate × 0.01))` samples at the source rate, power summed over all channels. Both are cached under the source's `contentKey` (section 8). UI stages: `Reading video… → Extracting audio…`.
3. **Transcription.** The router (transcription spec) picks ElevenLabs Scribe v2, whisper.cpp or Apple SpeechTranscriber from the user's choice and the language. The engine output is normalised into one word shape, then Core post-processing runs in the fixed order of editing spec 5.0: `cleanWords` → `tightenIntoSound` (gapless timings) → `refineWordBoundaries` → `findUnlabeledSpeech` (non-verbatim engines) → ids → pauses. Fillers are derived from text, never stored. The result is the immutable `Transcript`. The raw engine response is cached so re-normalisation never re-transcribes. Media leaves the machine only if the user chose ElevenLabs.
4. **Editing.** Every command (cut, restore, correct, cut fillers, tighten pauses, restore cuts, make clip, nudge clip edge) is a pure reducer `EditState × Command → EditState`. `EditHistory` keeps snapshots for undo, at most 500 steps, one step per command ("Cut fillers" is one step). macOS bridges `EditHistory` to the window's `UndoManager`; Windows binds Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z to it.
5. **Plan.** `EditPlan.build(transcript, editState, activeClip, duration, sampleRate)` produces merged cut sample ranges, kept ranges, `mapTime`, `sourceTime` and the join list with fade lengths `min(round(0.005 × sr), floor(len / 2))`. The plan is a value; every preview rebuild and every export derives a fresh one.
6. **Captions.** `CaptionTrack.build(plan, transcript, corrections, style, transforms)` maps kept words to the edited timeline and pages them (captions spec). Layout uses an injected `GlyphShaper` (CoreText on macOS, HarfBuzz on Windows) with integer font-unit decisions. The rasterizer draws glyph outlines.
7. **Preview.** Section 5 (macOS) and section 6 (Windows). Plan changes rebuild the preview within 150 ms (debounced) and keep the playhead at the same **source** time.
8. **Clips.** The clip finder sends the numbered transcript (text only) to the chosen connector and validates the reply with the canonical schema and `finalizeClips` (LLM spec). A successful run appends its `aiResult` and adds one selected `ClipRange` per suggestion in one undo step (AI spec 11.8, editing spec 10.6). Manual clips (select words, ⌘K / Ctrl+K) need no key.
9. **Export.** An `ExportJob` is `{target: fullEdit | clip(id), aspect: source | 16:9 | 9:16 | 1:1, captionStyle, quality, outputURL, writeSRT}`; the Export sheet fills it from the project's `export` and `captions.styleId` and writes the user's choices back to the project. Jobs run sequentially per window. Output is MP4, H.264 High, 4:2:0 8-bit, BT.709 tagged, AAC-LC 48 kHz stereo 160 kbps, moov first. Files are written to `<name>.partial` in the destination folder and renamed on success.
10. **Share.** M1: copy caption, reveal file, open X intent, open LinkedIn composer (publishing.md). M2: VoxConvo direct publish.

### 4.1 Export presets (both platforms)

| Aspect | Output size | H.264 bitrate at 30 fps | Framing (M1) |
|---|---|---|---|
| Source | `normalizedSize(w, h)`: `scale = min(1, 1920 / max(w, h))`, each side `max(2, round(v × scale / 2) × 2)` | `8 Mbps × (outW × outH) / (1920 × 1080)`, minimum 2 Mbps | none |
| 16:9 | 1920×1080 | 8 Mbps | centre crop of the oriented source |
| 9:16 | 1080×1920 | 8 Mbps | centre crop |
| 1:1 | 1080×1080 | 6 Mbps | centre crop |

- Crop: for an oriented source `W×H` and target aspect `a = outW / outH`: `cropH = min(H, W / a)`, `cropW = cropH × a`, centred, then scaled to the output size (Lanczos on export, bilinear on preview). M2 face-tracked reframe moves the crop centre; the crop size rule stays.
- Quality `High` multiplies the bitrate by 1.5. Frame rate: the nearest of {24, 25, 30, 50, 60} to the source nominal rate (a tie picks the lower rate), at most 60; 50 and 60 fps multiply the bitrate by 1.5. The bitrate in bits per second is rounded half up (`floor(x + 0.5)`) after the multipliers. GOP: 2 seconds. Output is constant frame rate.
- An export whose plan keeps zero samples is refused with `everythingCut`.
- SRT sidecar: one cue per caption page on the edited timeline, `HH:MM:SS,mmm --> HH:MM:SS,mmm`, UTF-8 without BOM, LF line endings, cues numbered from 1.
- Both platforms test the size, crop, frame-rate and bitrate rules above against the hand-written cases in `shared/fixtures/export/presets.json` (`{"schema": "voxclip-export-fixture/1", "cases": [{"source": [w, h], "sourceFps", "aspect", "quality", "expected": {"size": [w, h], "crop": [x, y, w, h], "fps", "videoBitrate"}}]}`; inputs avoid rounding ties).

### 5.2 Composition from kept sample ranges

- The CMTime timescale is the **source audio sample rate** (48,000 for video-only sources). Each kept range `[startSample, endSample)` is inserted back to back into one composition video track and one composition audio track: `insertTimeRange(CMTimeRange(start: CMTime(value: k.start, timescale: sr), end: CMTime(value: k.end, timescale: sr)), of: sourceTrack, at: cursor)`.
- Audio is sample-exact; video joins land on the frame displayed at that time (within one frame).
- A clip export is the same builder with the clip range layer active (clip head and tail are `range` segments in the plan).
- Rebuilds are O(kept ranges). The preview debounces rebuilds by 150 ms.

### 5.3 Join fades: MTAudioProcessingTap

- Media code builds `EditPlan` only from `sampleRate`, `totalSamples`, `cuts` and `kept`; Core derives the output length and the join fades (editing 2.7). Media tests use real kept ranges for clip edges and zero-length fade sides, never hand-set derived fields.
- `AVMutableAudioMixInputParameters.setVolumeRamp` is **not** used: ramps shorter than about 25 ms do not reach silence (measured: a 5 ms ramp left the join at about 0.28 of full level).
- The tap is created with `kMTAudioProcessingTapCreationFlag_PostEffects` and attached to the composition audio track's mix parameters. The same `AVAudioMix` serves `AVPlayerItem.audioMix` and `AVAssetReaderAudioMixOutput.audioMix`.
- The context is an immutable `final class FadeContext: @unchecked Sendable` holding the sorted join list (`ContiguousArray` of `(outSample, fadeOutLen, fadeInLen)` on the edited timeline). `gain(s)` binary-searches it: inside a fade-in of length `N` starting at `j`, `gain = (s − j) / N`; inside a fade-out ending at `j`, `gain = (j − 1 − s) / N`; otherwise 1. Kept parts that start at source sample 0 get no fade-in; parts that end at `totalSamples` get no fade-out. The gain function itself lives in Core (`EditPlan.joinGain`) so Windows uses the identical code path.
- If the tap's processing rate differs from the plan rate, `prepare` rescales the join positions once.
- **Sample position.** In the process callback, call `MTAudioProcessingTapGetSourceAudio` with a non-NULL `timeRangeOut`. `s0 = round(timeRangeOut.start.seconds × planRate)` (after the one-time rescale above), and frame `k` of the buffer is edited sample `s0 + k`. Never keep a running sample counter across callbacks: it is wrong after seeks, scrubbing, rate changes (J/K/L) and item replacement.
- The process callback runs on a real-time thread: **no allocation, no locks, no Swift concurrency, no logging** inside it.
- Acceptance: on the fixture `joins-tone` (section 9.5) with 59 joins over a 0.4-amplitude tone, every sample within ±3 samples of a join has `|x| < 0.01`; the edited audio's sample count equals `plan.outputSamples`; the cross-correlation lag against the plan is 0 samples at 10%, 50% and 90% of the output. In preview, after seeking to 3 random positions, the same `|x| < 0.01` holds within ±3 samples of the next join (tapped audio captured through a test hook).

### 5.4 FrameCompositor (preview and export)

- `final class FrameCompositor: NSObject, AVVideoCompositing, @unchecked Sendable`. `sourcePixelBufferAttributes`: `420v` and `BGRA`, Metal-compatible. `requiredPixelBufferAttributesForRenderContext`: `BGRA`, Metal-compatible. `supportsHDRSourceFrames` is not implemented, so AVFoundation converts HDR sources to SDR BT.709 before they reach the compositor.
- Instruction: `final class RenderInstruction: NSObject, AVVideoCompositionInstructionProtocol, @unchecked Sendable` holding immutable snapshots: time range, source track id, orientation, `CaptionTrack`, `CaptionStyle`, placement, crop track, output size. `containsTweening = true` so every frame is requested (captions animate). `enablePostProcessing = false`.
- `startRequest`: take the source frame, `CIImage(cvPixelBuffer:).oriented(orientation)`, crop to the crop rect at `compositionTime`, scale to `renderSize` (Lanczos for export, affine bilinear for preview) with one `CIContext(mtlDevice:, options: [.cacheIntermediates: false])`, render into `renderContext.newPixelBuffer()`. Then lock the buffer, wrap it in a premultiplied BGRA `CGContext` in sRGB (gamma-encoded blending, matching Skia on Windows), and call `CaptionRasterizer.draw(page, at: compositionTime)`. Finish with `finish(withComposedVideoFrame:)`. The body runs inside `autoreleasepool` on the compositor's own serial `renderQueue`.
- `cancelAllPendingVideoCompositionRequests` bumps a generation counter (`Mutex<UInt64>`); queued requests with an older generation finish with `finishCancelledRequest()`.
- Caption raster cache: LRU keyed by `(pageIndex, styleHash, renderSize, animationFrameKey)`, capped at 64 MiB per window. Only static states are cached; animated frames are drawn directly.
- Preview `renderSize` = the on-screen video rect in physical pixels, capped at the export size. Because caption sizes scale with the frame's short edge (captions 5.3, ADR-R16), preview is pixel-proportional to export.
- Caption and style changes do not rebuild the composition: a new `AVVideoComposition` (new instruction snapshot) is assigned to `item.videoComposition`. AVPlayer re-renders the current frame even when paused. Drag updates are throttled to 30 Hz.
- Because the minimum is macOS 26, the newer Swift-concurrency wrappers (`AVVideoComposition.Configuration`, `AVAssetWriter.inputPixelBufferReceiver`, `AVAssetReaderOutput.Provider`) may be used where they simplify code; behaviour must match this section.

### 5.5 Preview with AVPlayer

- `AVPlayerItem(asset: graph.composition)` with `videoComposition` and `audioMix` from the same graph. The video surface is an `AVPlayerLayer` in an `NSView` wrapped with `NSViewRepresentable` (no system transport controls).
- Plan change: `src = oldPlan.sourceTime(fromEdited: player.currentTime)`; build; `replaceCurrentItem`; `seek(to: newPlan.editedTime(fromSource: src), toleranceBefore: .zero, toleranceAfter: .zero)`. The last frame stays visible while the new item becomes ready (typically 100–300 ms).
- Scrubbing: while dragging, seeks use ±0.1 s tolerance and coalesce (one seek in flight, newest target wins). On release or word click, an exact seek.
- Transcript highlight: `addPeriodicTimeObserver(forInterval: 1/30 s, queue: .main)`; the playing word follows editing spec 7.8: `s = plan.sourceTime(t)`, then the first uncut `word` item with `start <= s < end` (binary search over source items by `start`, then a short forward scan); the UI changes only when the word changes.

### 5.6 Export (AVAssetReader → AVAssetWriter)

- Reader: `AVAssetReaderVideoCompositionOutput(videoTracks:, videoSettings: [kCVPixelBufferPixelFormatTypeKey: kCVPixelFormatType_32BGRA])` with the export video composition; `AVAssetReaderAudioMixOutput` with LPCM Float32 48 kHz stereo and the tapped audio mix. `alwaysCopiesSampleData = false`.
- Writer: `AVAssetWriter(outputURL: <dest>.partial, fileType: .mp4)`, `shouldOptimizeForNetworkUse = true` (moov first, the `+faststart` equivalent).
- Video input: `AVVideoCodecType.h264`, width/height from section 4.1, `AVVideoCompressionPropertiesKey: [AVVideoAverageBitRateKey, AVVideoExpectedSourceFrameRateKey: fps, AVVideoMaxKeyFrameIntervalKey: 2 × fps, AVVideoAllowFrameReorderingKey: true, AVVideoProfileLevelKey: AVVideoProfileLevelH264HighAutoLevel, AVVideoH264EntropyModeKey: AVVideoH264EntropyModeCABAC]`, `AVVideoColorPropertiesKey`: BT.709 primaries, transfer function and YCbCr matrix. The same colour properties are set on the video composition. `RequireHardwareAcceleratedVideoEncoder = true` requires VideoToolbox hardware; no software fallback is accepted for this path.
- An internal optional writer-boundary observer may read selected composed BGRA pixels synchronously before successful video append. It stores only pixel values and presentation timestamps, releases the pixel-buffer read lock, and is absent in production exports. The observer never changes append, cancellation or frame counts (ADR-R22).
- Audio input: `kAudioFormatMPEG4AAC`, 48,000 Hz, 2 channels, 160,000 bps.
- The movie timescale is 48,000, so audio edit-list durations keep every exported sample, including edits that do not fall on the 1/600 s grid. The video input may keep its 600-tick timescale.
- Edited WAV output has exactly the plan's sample count. If a container rounds its audio end past the last decodable PCM sample, check the source's final second and pad only the missing tail of the last kept range. Any other shortfall is an export error; interior gaps are never padded.
- Pumping: `requestMediaDataWhenReady` on two serial queues; `copyNextSampleBuffer` → `append`; `markAsFinished` on nil. Progress = last appended video PTS / composition duration, published at ≤ 10 Hz with phases `preparing`, `encoding`, `finalizing`.
- Each pump has its own `AVAssetReader` over the same composition and time range (one with the video-composition output, one with the audio-mix output), so neither output can stall waiting for the other to be read.
- Cancellation and failure: task cancellation or the first pump error stops both pumps at their next sample boundary. Pumps only stop pulling; no reader is cancelled while either pump can still be inside `copyNextSampleBuffer`. After both pumps have returned, both readers are cancelled, then the writer is cancelled and the partial file is deleted. Neither path decodes the rest of the timeline.
- A stop always completes: each pull runs so that a stopped pump can return without waiting for a `copyNextSampleBuffer` call that never returns (the blocked call is abandoned, and its reader is released when the call returns). Within 2 s of a stop, the export has cancelled the writer (once no append is in flight), deleted the partial file and returned `cancelled` or the first error.
- The two readers each get their own copy of the composition, so they share no composition object.
- M1 exports H.264 only (X, LinkedIn and VoxConvo accept it everywhere). HEVC for "Save to disk" may come later.
- Measured reference: about 10× realtime at 1080p30 on M3 Max including captions; budget 3–5× on a base M1.

### 5.7 Recording (M2)

`AVCaptureSession` with `AVCaptureVideoDataOutput` (420v) and `AVCaptureAudioDataOutput` (LPCM) on one serial `writerQueue`, writing a `.mov` master (HEVC 12 Mbps, LPCM 48 kHz 24-bit, `movieFragmentInterval` 2 s). Session start time is the first audio buffer after the 3-second countdown. The preview is mirrored for front cameras; the recording is not. The same audio buffers feed live transcription at 16 kHz.

### 6.2 Probe and decode

- `avformat_open_input` + `avformat_find_stream_info`; best video and audio streams via `av_find_best_stream`. Rotation from the stream's display-matrix side data (`av_display_rotation_get`), quarter turns only; the oriented size swaps width and height for 90 and 270.
- Hardware decode: `av_hwdevice_ctx_create(AV_HWDEVICE_TYPE_D3D11VA)` with a `get_format` callback selecting `AV_PIX_FMT_D3D11`. Fall back to software decode (threads = logical cores, max 8) if device creation or the codec fails. HEVC decodes this way without the Store "HEVC Video Extensions".
- Hardware frames are copied to system memory with `av_hwframe_transfer_data` (NV12 or P010) before scaling.
- Frame-exact seek: `av_seek_frame(ctx, stream, ts, AVSEEK_FLAG_BACKWARD)`, `avcodec_flush_buffers`, then decode forward until `best_effort_timestamp ≥ target − ½ frame`.
- Audio: decode to float planar, `swr_convert` to float32 interleaved at the **source audio sample rate**, mixed down to stereo (mono is duplicated). The plan's sample grid is the source sample rate, exactly as on macOS.
- The Windows 0.1 pin guarantees the codec subset in `tools/ffmpeg-build/components.md`, not every codec inside an accepted container. ProRes, DNxHD/HR, MJPEG, MP3, AC-3/E-AC-3, ALAC and FLAC tracks are currently unsupported; if the selected video or first audio track uses one, import reports `decodeFailed`. This differs from macOS system-codec coverage and must be revisited before claiming full container parity.

### 6.3 Preview engine

The preview plays the edited timeline with the audio clock as master. Its per-frame compose function is the exporter's compose function at preview size, so preview equals export.

```text
 EditPlan (immutable snapshot, swapped atomically)
   │
   ├─ AudioProducer thread: decode kept ranges by sample index ─► join gains ─► swr to device rate ─► ring buffer (≥ 2 s ahead)
   │                                                                                                   │
   │                                                                     WasapiOut (shared mode, event-driven) pulls from the ring buffer
   │                                                                     audio clock = frames played by the device / device rate
   │                                                                                                   ▼
   ├─ VideoDecoder A ("current")    ─┐                                   Presenter (UI thread, CompositionTarget.Rendering):
   ├─ VideoDecoder B ("look-ahead") ─┴─► decode to BGRA (BT.709),        newest frame with editedPts ≤ clock
   │                                      compose: crop, scale, captions → copy BGRA into WriteableBitmap.PixelBuffer
   │                                      Skia captions at edited t       → Invalidate()
   │                                      └─► bounded frame channel (capacity 6) ──────────────────────────►
```

Rules:

1. **Clock.** Edited time = seek origin + (frames rendered by the device, from `WasapiOut.GetPosition()` in bytes / bytes per frame) / device rate. Video follows the clock; the clock never follows video. Video-only sources use a `Stopwatch` clock.
2. **Audio.** The `AudioProducer` walks the plan's kept ranges, decodes each by sample index (seek to `max(0, start − 0.5 s)`, discard samples before `kept.start`, take exactly `kept.end − kept.start` samples), multiplies by Core's `EditPlan.joinGain` (section 5.3), resamples to the device mix format with swr and fills the ring buffer. The edited timeline has no gaps, so playback is gapless by construction.
3. **Video.** Decoder A serves the current kept range. When the clock is within 2.0 s of the next join, decoder B seeks to the next kept range's start and decodes up to its first frame. At the join, A and B swap roles. A seek target less than 2 s ahead of A's position decodes forward instead of seeking.
4. **Mapping.** For each decoded frame with source PTS `ts` inside the current kept range, `editedPts = plan.mapTime(ts)`. Frames whose source PTS lies inside a cut are dropped.
5. **Compose.** On the decoder thread, `VideoDecoder` converts progressive planar or semiplanar 4:2:0 (8-bit or 10-bit) to BGRA with an explicit BT.709 inverse matrix and identical fixed-point rounding on x64 and ARM64. AVX2 and ARM64 AdvSimd accelerate chroma interpolation and BGRA packing with the scalar path's coefficients and rounding; a portable vector path remains for other SIMD machines. The vertical chroma pass reads each plane layout and sample depth directly, including the 10-bit planar clamp and P010 shift, before the same fixed-point interpolation. It reads each frame's full/limited range and signed plane strides. Left, centre/unspecified and top-left chroma locations use their declared geometry; top, bottom-left and bottom locations, interlaced frames, non-BT.709 matrices and other pixel formats use `sws_scale`. An unspecified matrix is assumed BT.709; known FCC, 601, SMPTE 240M and BT.2020 non-constant matrices use their source coefficients in the native fallback, with BT.709 output. Other explicitly tagged matrices retain the existing BT.709 swscale assumption pending the HDR contract. A size change scales the converted BGRA. The shared compose function crops and scales to the preview size, then the Skia caption renderer draws the caption state at `editedPts` into an `SKSurface` that wraps the BGRA buffer with **no colour space** (gamma-encoded blending, matching CoreGraphics). Frame buffers are reused between frames.
6. **Present.** On every `CompositionTarget.Rendering` tick the presenter takes the newest frame with `editedPts ≤ clock` (dropping older ones) and copies it into a `WriteableBitmap` shown in an `Image` (`Stretch="Uniform"`) on a black stage. If no new frame is due, nothing is copied.
7. **Preview size** = the stage's rendered size × `XamlRoot.RasterizationScale`, capped at the export output size and at 1920 on the long edge. A size change flushes the pools.
8. **Seek and scrub.** Pause the device, flush the ring buffer and both decoders, compute `src = plan.sourceTime(edited)`, seek decoder A exactly and the audio producer to the edited sample offset. During a drag, seeks coalesce (one in flight, newest wins) and the first decoded frame at or after the target is presented.
9. **Plan change.** The new plan snapshot replaces the old one atomically; the playhead keeps its source time (`src = old.sourceTime(t)`, `t' = new.mapTime(src)`), then the engine seeks to `t'`.
10. **Caption-only change.** Swap the caption snapshot; the next composed frame uses it. While paused, the current frame is re-composed once.
11. A later zero-copy path (D3D11 shared texture into a `SwapChainPanel`) may replace steps 5–6 without changing the clock or plan logic. Not in M1.

Acceptance (the on-demand `--long-hevc` clip of section 9.5): a 10-minute 1080p HEVC clip with 200 cuts plays without audible gaps or clicks on an x64 iGPU and on a Snapdragon ARM64 laptop; A/V offset stays within ±40 ms across 50 consecutive joins; a word click while paused shows the right frame within 150 ms.

### 6.4 Export: decode → overlay → encode

- **Video.** Output frames sit on a constant grid `te = k / fps`, `k = 0 … round(plan.duration × fps) − 1`. For each `te`: `ts = plan.sourceTime(te)`; decode forward until the next frame's PTS > `ts` and keep the latest frame with PTS ≤ `ts`; seek only when the next kept range starts more than 2 s past the decoder position. One decoder suffices because kept ranges are monotonic.
- **Compose.** Same function as preview at output size: crop and scale with `sws_scale` (`SWS_LANCZOS`), Skia captions at `te`, then BGRA → NV12 with `sws_scale` using the BT.709 matrix and limited range. Hardware encoders require NV12 input.
- **Audio.** Kept ranges by sample index, join gains from Core, `swr` to 48 kHz stereo float, FFmpeg's native `aac` encoder at 160 kbps (frame size 1024), PTS = running output sample count.
- **Mux.** `avformat_alloc_output_context2(…, "mp4", …)`, stream time bases `1/fps` (video) and `1/48000` (audio), `movflags=+faststart`, codec tags `avc1` and `mp4a`, video colour tags `color_primaries=AVCOL_PRI_BT709`, `color_trc=AVCOL_TRC_BT709`, `colorspace=AVCOL_SPC_BT709`, `color_range=AVCOL_RANGE_MPEG`. Write to `<dest>.partial`, rename on success, delete on failure or cancel.
- **Progress** = encoded frames / total frames at ≤ 10 Hz with phases `preparing`, `encoding`, `finalizing`. **Cancellation** through `CancellationToken`, checked per frame.

### 6.5 HDR sources

PQ or HLG sources are tone-mapped to SDR BT.709 before compose with the libavfilter graph `zscale=t=linear:npl=100,format=gbrpf32le,zscale=p=bt709,tonemap=hable:desat=0,zscale=t=bt709:m=bt709:r=tv,format=nv12` when the pinned build contains `zscale` (verify at pin time). Otherwise the frame is converted with swscale and the export shows the InfoBar "This video is HDR. Colours are converted to standard range and may look flatter." macOS needs no equivalent (AVFoundation converts, section 5.4).

### 6.6 Encoder ladder

At first launch, and whenever the GPU adapter LUID, the driver version or the FFmpeg build changes, `EncoderProbe` tries in order:

| Order | Encoder | Options |
|---|---|---|
| 1 | `h264_nvenc` | `preset=p5`, `tune=hq`, `rc=vbr`, `b`, `maxrate=1.5×b`, `bufsize=2×b`, `profile=high`, `g=2×fps`, `bf=2` |
| 2 | `h264_qsv` | `preset=medium`, `b`, `maxrate=1.5×b`, `profile=high`, `g=2×fps` (absent on ARM64) |
| 3 | `h264_amf` | `usage=transcoding`, `quality=balanced`, `rc=vbr_peak`, `b`, `maxrate=1.5×b`, `profile=high`, `g=2×fps` |
| 4 | `h264_mf` | `hw_encoding=1`, `rate_control=pc_vbr`, `b`, `g=2×fps`, and `AVCodecContext.profile = AV_PROFILE_H264_HIGH` (100) set on the context: `h264_mf` rejects the string option `profile=high` with EINVAL, and its default can be Constrained Baseline, so always set High this way |
| 5 | `h264_mf` (software) | `hw_encoding=0`, otherwise as row 4 (including the context-level High profile). Microsoft's own H.264 encoder MFT that ships with Windows; used only when no hardware encoder MFT exists (VMs, machines without a GPU encoder). It is not x264 and adds no GPL code. Slower; the export sheet shows "Exporting without hardware acceleration" once |

Probe: `avcodec_find_encoder_by_name`; open at 1280×720 NV12 30 fps with the options above; encode 3 black frames; flush; success = at least one packet. The first success wins and is cached in `<data>\Cache\encoders.json` keyed by `{adapterLuid, driverVersion, ffmpegVersion}`. If an encode fails mid-export with the cached encoder, the job restarts once with the next encoder in the ladder and updates the cache. If none works (for example Windows N editions without the Media Feature Pack): `encoderUnavailable`, whose message names the Media Feature Pack.

Acceptance: average bitrate within ±15% of target on the on-demand `--motion-60s` clip (section 9.5) for every encoder present on the test machine. On Windows, `ffprobe` reports `profile=High`, `pix_fmt=yuv420p`, `color_primaries=bt709`, `color_transfer=bt709`, `color_space=bt709`, and limited (`tv`/MPEG) range. Hardware Windows encoders retain decoded canonical RGB ±3. For **software Windows `h264_mf` only**, preencoder RGB stays within ±3 of canonical and decoded Y, U and V at the same frame and pixel each stay within ±1 of actual NV12 sent to the encoder, with exact High/yuv420p/BT.709 limited metadata and independent BT.709 coefficients (ADR-R21). For **required-hardware macOS `h264_videotoolbox` only**, actual composed BGRA at the writer boundary stays within ±3 of canonical; decoded Y/U/V each stays within ±1 of the independent half-up rounded BT.709 limited transform of that BGRA at the same frame, PTS and pixel. AVFoundation/CoreMedia inspect H.264 SPS High profile, 8-bit 4:2:0, MPEG limited range and BT.709 primaries/transfer/matrix; no `ffmpeg` or `ffprobe` prerequisite is imposed on macOS. A finite decoded RGB check against the inverse YUV transform is bounded at ±2 to allow decoder rounding; it does not compare decoded RGB to canonical (ADR-R22). The limited-range inverse can amplify a one-code chroma difference beyond three RGB codes.

## 7. Concurrency model

### 7.1 macOS (Swift 6 strict concurrency)

- Swift 6 language mode, complete checking, in every target. Core domain types are `Sendable` value types (`struct`, `enum`). Shared mutable state lives in actors or on the main actor.
- **Main actor:** all SwiftUI views and `@Observable` models: `AppModel` (app-wide settings mirror, connector status, update status) and one `EditorModel` per document window (project value, `EditHistory`, selection, playhead, derived plan, export state, and the document's current file URL from `ReferenceFileDocumentConfiguration.fileURL`, used to compute `relativePath`). Models mutate only on the main actor.
- **Documents:** section 2.6. `NSDocument` owns autosave timing and writing; `VoxClipDocument.snapshot(contentType:)` returns the project value with `relativePath` computed from the stored file URL, and a file URL change marks the document dirty so the next autosave rewrites it.
- **Actors:** `TranscriptionService`, `ClipFinder`, `ExportQueue` (one per window, runs jobs sequentially), `ModelStore` (downloads, verification, installed index), `CacheStore` (index, eviction), `SettingsStore` (atomic JSON writes), `UpdateChecker`.
- **AVFoundation confinement:** AVFoundation object graphs (`AVMutableComposition`, `AVPlayerItem`, readers, writers) are created and used inside one isolation domain and never passed across. The preview graph is built on the main actor (after async track loading) and handed to `AVPlayer` there. The exporter builds its own graph inside `ExportQueue` from `Sendable` inputs (source URL, `EditPlan`, `CaptionTrack`, `CaptionStyle`, `OutputSpec`). Only these value descriptions cross actors.
- **Framework callback threads:** `FrameCompositor` work runs on its serial `renderQueue` with immutable inputs and a `Mutex` generation counter. The fade tap callback is real-time (section 5.3). Capture delegates (M2) run on `writerQueue`. Events from these queues reach the main actor through `Task { @MainActor in … }`, coalesced, and only when UI-visible.
- **Long work** runs in `Task`s owned by the window's model; closing the window cancels them. Every loop checks `Task.isCancelled` (or calls `try Task.checkCancellation()`).
- **Progress** flows as `AsyncStream` / `AsyncThrowingStream` consumed on the main actor, throttled to 10 Hz; accessibility announcements at every 10%.
- **Debounce:** composition rebuild 150 ms after the last edit; caption drag updates at ≤ 30 Hz; settings writes 500 ms.
- `@unchecked Sendable` and `nonisolated(unsafe)` are allowed only on the compositor, its instruction, the tap context and C-callback boxes (whisper.cpp), each with a comment stating the invariant.

### 7.2 Windows (.NET async + DispatcherQueue)

- **UI thread:** WinUI `DispatcherQueue`. View models (CommunityToolkit.Mvvm `ObservableObject`) are created and mutated only on the UI thread. Core types are immutable records.
- **Async services** (`TranscriptionService`, `ClipFinder`, `ExportQueue`, `ModelStore`, `CacheStore`, `SettingsStore`) expose `Task`-returning methods with a `CancellationToken` and an `IProgress<T>` created on the UI thread (so callbacks marshal back automatically). CPU-bound work uses `Task.Run`; decoder and audio loops run on dedicated named threads (`vc-audio`, `vc-dec-a`, `vc-dec-b`, `vc-export`).
- **Rules:** no `async void` except event handlers; no `.Result` or `.Wait()` on the UI thread; `ConfigureAwait(false)` in Core and Media; UI-bound continuations use `DispatcherQueue.TryEnqueue` explicitly.
- **Preview engine** threads are described in section 6.3. Hand-offs use bounded `System.Threading.Channels.Channel<T>` (frames) and a lock-free single-producer/single-consumer ring buffer (audio). Plan and caption snapshots are swapped with `Interlocked.Exchange`.
- **Native lifetimes:** FFmpeg contexts are freed on their owning thread in `finally` blocks; every native allocation has a `SafeHandle` wrapper; the preview engine is `IAsyncDisposable`.

## 8. Caching

### 8.1 Source content key

`contentKey = lowercase hex(SHA-256( UTF-8 "voxclip-source-v1\n" + decimal(fileSizeBytes) + "\n" + firstMiB + lastMiB ))`, where `firstMiB` and `lastMiB` are the first and last 1,048,576 bytes (if the file is smaller than 2 MiB, the whole file once and no `lastMiB`). The key survives moves and copies, and is used both for cache lookup and to verify a relinked source.

### 8.2 Cache layout (per source)

```text
<data>/Cache/<contentKey>/
  meta.json                 { "schema": "voxclip-cache/1", contentKey, createdAt, lastAccessAt, bytes,
                              envelope: { sampleRate, frameSeconds: 0.01, count } }
  audio-16k.wav             16-bit PCM mono 16 kHz, round(duration × 16000) samples
  envelope-10ms.f32         little-endian binary32 frames, exactly editing spec 5.1 level[] (frameSize = max(1, jsRound(rate × 0.01)), power summed over channels)
  transcripts/<engine>-<model or "none">-<language or "auto">-<opts8>.json   raw engine results (transcription spec 14.1; the normalised transcript lives in the project)
  thumbs/strip-160.jpg      filmstrip, 160 px high
  faces/                    M2 detections
<data>/Cache/encoders.json        Windows encoder probe result
<data>/Cache/llm-models.json      refreshed LLM model lists per connector (AI spec section 9; no keys)
<data>/apple-speech-locales.json  macOS: reserved SpeechTranscriber locales and last use (transcription spec section 10.3)
```

Topic specs may add files inside a cache entry (for example the transcription spec's per-engine files); they must follow the atomic-write and eviction rules below.

- Writes are atomic (temp file in the same directory, then rename).
- Eviction: least recently used by `lastAccessAt`, cap 5 GB by default (Settings → General → "Cache size limit": 2 / 5 / 10 / 20 GB), run in the background 30 s after launch and after each import. Entries referenced by an open project are never evicted. "Clear cache" removes everything not in use.
- Models are not cache: only the user removes them (Settings → Transcription).
- A missing or corrupt cache entry is never an error: it is recomputed.

## 9. Headless CLI (both platforms)

The Windows CLI checks the separate per-user runtime agreement before dispatching normal commands, reading input paths, creating media services, or reading provider keys. `voxclip-cli --runtime-terms` prints the two exact bundled Microsoft component terms and their combined SHA-256 offline; `voxclip-cli --accept-runtime-terms <SHA-256>` records explicit acceptance. `--json` works with both commands. Without a matching receipt, normal commands return `runtimeTermsRequired` and exit 7, with those actionable commands in the message; missing or altered pinned terms return `runtimeTermsUnavailable` and exit 7. Parsed help and version actions remain available; literal `--help` or `-h` media arguments after `--` do not bypass the gate. The two fenced licence bodies are extracted from the installed root `THIRD_PARTY_NOTICES.md`, with CRLF converted to LF before extraction and hashing, checked against pinned individual SHA-256 values, and combined into a content-bound hash. The receipt is an atomic, versioned hash-only file under the per-user data root, separate from `settings.json`. `VOXCLIP_DATA_DIR` isolates it along with the rest of user data for offline tests. The Windows app uses this same Core agreement before constructing normal services or opening a project; the WinUI prompt itself may load platform UI modules. Both app and CLI fail closed when terms are absent or corrupted. See ADR-R23 and design §9.

`voxclip-cli` exists for end-to-end tests, CI and agent-driven verification. macOS: product `voxclip-cli`, also shipped as `VoxClip.app/Contents/MacOS/voxclip-cli`. Windows: `VoxClip.Cli` → `voxclip-cli.exe`, shipped next to `VoxClip.exe`. Same flags, same output, same exit codes on both.

### 9.1 Primary form (export)

```text
voxclip-cli --open <project.voxclip | media file> --export <out.mp4>
            [--style <captionStyleId> | --style off]          style id from shared/caption-styles (e.g. vox-highlight); default: the project's style, else "off"
            [--aspect source | 16:9 | 9:16 | 1:1]               default: the project's aspect, else "source"
            [--clip <clipId> | --range <startWordIndex>:<endWordIndex>]
            [--transcript <transcript.json>]                    use a stored Transcript instead of transcribing
            [--engine whisper | apple | elevenlabs] [--model <modelId>] [--language <bcp47>]
            [--cut-fillers] [--tighten-pauses]                  applied in this order before export
            [--quality standard | high] [--fps <n>] [--srt <out.srt>]
            [--audio-out <edited.wav>]                          test hook: also write the edited, faded audio as 32-bit float WAV
            [--json] [--quiet]
```

Behaviour:

1. `--open` a `.voxclip` project: load it and relink media by the project rules (section 3) without prompts; a `contentKey` mismatch is exit 3.
2. `--open` a media file: create an in-memory project. With `--transcript`, load that file: one JSON object exactly as `transcript` is stored in a project (`project.schema.json` `$defs/transcript`), used as is with no post-processing (stored timings never change); a file that does not decode is exit 3. Otherwise transcribe with `--engine` (default: whisper with the first installed model that matches `--language`, else exit 7).
3. Select the export scope first: `--clip` (an existing clip) or `--range` (a new clip over those words) when given, else an opened project's stored `activeClipId`, else the whole take. Then apply `--cut-fillers`, then `--tighten-pauses` (the same reducers as the UI), which act within that scope as they do in the app. So `--clip b --cut-fillers` cuts the fillers of clip `b`, whichever clip was active when the project was saved. A new in-memory project (media-file input) sets `pauseThresholdSeconds` as an import does (editing.md 2.5: 0.8 when the transcript is refined, else 1.0).
4. Export with the same exporter as the app. Write `--srt` if asked.

### 9.3 Output and exit codes

Before preparing an export, the CLI checks the editing summary in the active clip or word-range scope. An empty output plan or `canExport == false` fails with `everythingCut` and exit 5, and no destination or sidecar is changed. An unknown clip or a word range outside the transcript is a bad argument (`usageError`, exit 2), and so is `--audio-out` for a source with no audio track ("This video has no audio track, so --audio-out has nothing to write.") and `--srt` when the effective caption style is `off` ("Captions are off, so --srt has nothing to write. Choose a caption style with --style."). SRT cues come from caption pages, and with captions off there are none. These argument checks run as soon as the source is probed, before transcription and before the `everythingCut` check, so the same flags give the same exit code on both platforms. They also cover an unknown `--clip` for a media-file input, which never has clips.

Other bad arguments are usage errors (exit 2) before the input is opened, with this copy on both platforms:
- `--fps` that is not a finite number above 0 and at most 60: "--fps must be greater than zero and at most 60".
- An output (`--export`, `--srt`, `--audio-out`) that is an existing folder or special file: "An output must be a file path, not a folder or special file". An output whose parent folder does not exist: "The output folder does not exist for {path}". Folders are never created.
- Outputs that overwrite an input or each other: "Output paths must not overwrite inputs or each other".
- `--transcript` when `--open` is a `.voxclip` project: "--transcript only applies when --open is a media file." A project keeps its own transcript.

Every output (video, edited WAV, SRT) is written to `<name>.partial` beside its destination, where the destination path is resolved through symlinks first. An existing regular file at a `.partial` path is a leftover from an earlier run and is replaced; a directory or symlink there is a bad argument. The WAV and SRT are finished before anything is published. Publication is all-or-nothing, in the order MP4, SRT, WAV: before the first rename, each existing destination is kept as a backup beside it (`<name>.rollback-<random>`, a copy-on-write clone where the file system supports one). If any rename fails, every destination already replaced is restored from its backup, or removed if it did not exist before, so a failure at any step leaves every existing destination unchanged. Every restore is attempted even if an earlier one fails. A backup whose restore fails is never deleted: it stays beside the destination, and the error (`exportFailed`) says "Couldn't put back {file name}. The previous version is saved as {backup file name}." Every other backup is deleted on success, failure and cancellation. Partial files are removed on success, failure and cancellation.

- Human-readable progress goes to **stderr**: one line per phase change, percentages at most once per second, nothing with `--quiet`.
- The edited WAV (`--audio-out`) is written at the plan's sample rate with exactly `plan.outputSamples` samples per channel; it is never resampled.
- `audioSampleRate` reports the 48,000 Hz export target on both platforms. For video-only output it stays 48,000, `audioSamples` is 0 and no audio track is written.
- `--json` prints exactly one JSON object on **stdout** at the end:

```json
{ "ok": true, "command": "export", "output": "/abs/out.mp4", "srt": null,
  "durationSeconds": 42.317, "width": 1080, "height": 1920, "fps": 30, "frames": 1270,
  "audioSampleRate": 48000, "audioSamples": 2031216, "videoCodec": "h264", "encoder": "h264_videotoolbox",
  "captionStyle": "vox-highlight", "aspect": "9:16", "elapsedSeconds": 6.4, "version": "0.1.0" }
```

On failure: `{ "ok": false, "command": "export", "error": { "code": "unsupportedContainer", "message": "…" }, "version": "0.1.0" }`.

| Exit | Meaning |
|---|---|
| 0 | Success |
| 1 | Unexpected failure |
| 2 | Usage error (unknown flag, bad value) |
| 3 | Input missing, unreadable, unsupported, or relink mismatch |
| 4 | Transcription failed |
| 5 | Export failed (including `everythingCut`) |
| 6 | Cancelled (SIGINT / Ctrl+C); partial output deleted |
| 7 | Missing key, model or connector (`keyMissing`, `modelMissing`, `cliNotInstalled`, `cliNotSignedIn`) |

### 9.4 Keys and environment

The CLI never reads the Keychain or DPAPI (an ad-hoc-signed build that reads a Keychain item created by the signed app triggers a login-password prompt). Keys come only from VoxClip-specific env vars: `VOXCLIP_ELEVENLABS_API_KEY`, `VOXCLIP_ANTHROPIC_API_KEY`, `VOXCLIP_OPENAI_API_KEY`, `VOXCLIP_XAI_API_KEY`, `VOXCLIP_GEMINI_API_KEY`. They never share a name with a CLI connector's own auth variables (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, …), so a key meant for VoxClip never silently changes how the user's `claude` or `codex` bills (AI spec 6.10). A debug build of the app launched with `VOXCLIP_NO_KEYCHAIN=1` uses the same env-var key provider (AI spec section 8.1). Other env vars: `VOXCLIP_DATA_DIR`, `VOXCLIP_SHARED_DIR`, `VOXCLIP_LOG_LEVEL` (`error|warn|info|debug`, default `info`). The CLI logs to stderr and, if `VOXCLIP_DATA_DIR` is set, also to `<data>/Logs/`.

### 9.5 End-to-end tests built on the CLI

Both platforms run the same cases against the committed synthetic media in `shared/fixtures/media` (below):

1. `fillers-chirp` with `--cut-fillers` (17 filler cuts): the `--audio-out` sample count == `plan.outputSamples`; cross-correlation lag of `--audio-out` against the plan-mapped source chirp < 48 samples at 8%, 50% and 94% of the output.
2. `joins-tone` with `--cut-fillers` (59 joins): in `--audio-out`, every sample within ±3 samples of a join has `|x| < 0.01`. Join checks always use `--audio-out` (pre-AAC PCM), never the decoded MP4, because AAC adds noise around a fade.
3. Captions (`vox-bold`, `vox-highlight`; one word per page, no hold) on `fillers-chirp`: bright pixels (luma ≥ 200) present in the caption area at the middle of each edited word, absent 0.12 s before and after it (every edited gap is at least 0.25 s).

## 10. Error handling

### 10.1 Rules

1. **Nothing is lost.** No error discards media, transcript or edits. Every user-facing error says what is still safe ("Your edits are saved.", "Your video is still here.").
2. **Errors are values.** Swift: `enum VoxClipError: Error, LocalizedError, Sendable`. C#: `sealed class VoxClipException` carrying a `VoxClipErrorCode`. The code strings are identical on both platforms (table below) so tests, the CLI and logs agree.
3. **Inline, not modal.** Errors appear where the action happened (macOS inline callout row, Windows `InfoBar`, the Export sheet, the Clips tab). Alerts are only for destructive confirmations.
4. **Cancellation is not an error.** It shows no message and logs at `info`.
5. **Retries.** Idempotent requests (transcription upload, LLM calls, model downloads, update checks) make up to 3 attempts on 429, 5xx and 529 with 1 s then 2 s backoff, honouring `Retry-After` up to 30 s; then one fallback model on LLM overload (LLM spec). **Publishing calls are never retried automatically** (publishing.md).
6. **Local never silently becomes cloud.** If a local engine fails, VoxClip offers ElevenLabs as a button; it never uploads on its own.
7. Provider error bodies are shown and logged truncated to 200 characters, after redaction.

## 11. Logging and redaction

### 11.1 Facade and sinks

Core defines `Log` with levels `error`, `warn`, `info`, `debug` and a category string (`import`, `transcribe`, `llm`, `export`, `preview`, `update`, `models`, `settings`, `share`, `publish`). Sinks:

| Sink | macOS | Windows |
|---|---|---|
| System | `os.Logger(subsystem: "com.voxconvo.voxclip", category:)`; interpolated values `privacy: .private` | none |
| File | `~/Library/Logs/VoxClip/voxclip.log`, rolled at 5 MB, 5 files kept | `<data>\Logs\voxclip.log`, rolled at 5 MB, 5 files kept |
| stderr | CLI only | CLI only |

Logging must never crash or block startup: file sink failures are swallowed after one system-log message. Writes go through a background queue (macOS) or channel (Windows). Help → "Reveal Logs" opens the folder in Finder / Explorer. Help → "Copy Diagnostics" copies version, OS, architecture, GPU and cached encoder (Windows), and the last 200 redacted log lines.

### 11.2 Redaction (Core `Redactor`, pure, fixture-tested)

This is the only redactor definition: the AI spec, the transcription spec, Voice Lab and the LLM catalogue refer to it, and the replacement text is always `[REDACTED]`. Every message passes through `Redactor.redact(_:)` before it reaches any sink. In order:

1. **Known secret values.** Every key or token loaded during the session (from the secret store, env vars or the device flow) is registered with the redactor; each occurrence is replaced with `[REDACTED]`. Values shorter than 8 characters are not registered.
2. **Authorization headers** (case-insensitive): `(authorization)(["']?\s*[:=]\s*["']?)((?:Bearer|Basic|Key|Token)\s+)?([^\s"',&]+)` → `$1$2$3[REDACTED]`. The scheme word is kept and the credential after it is replaced, whatever the scheme.
3. **Other header and field patterns** (case-insensitive): `(x-api-key|xi-api-key|x-goog-api-key|api[-_]?key|access[-_]?token|refresh[-_]?token|client[-_]?secret|password|secret|token)(["']?\s*[:=]\s*["']?)([^\s"',&]+)` → keep groups 1 and 2, replace group 3 with `[REDACTED]`. Then **bearer tokens** anywhere: `Bearer\s+[A-Za-z0-9._~+/=-]+` → `Bearer [REDACTED]`.
4. **URL query values** for `key`, `api_key`, `token`, `access_token`, `code`, `device_code`, `user_code`, `signature`, `sig` → the value becomes `[REDACTED]`.
5. **Key shapes:** `sk-ant-[A-Za-z0-9_-]{16,}`, `sk-(proj-)?[A-Za-z0-9_-]{20,}`, `xai-[A-Za-z0-9]{20,}`, `AIza[0-9A-Za-z_-]{35}`, `sk_[0-9a-f]{32,}` (ElevenLabs), `gh[pousr]_[A-Za-z0-9]{36,}`, JSON Web Tokens `eyJ[A-Za-z0-9_-]+\.[A-Za-z0-9_-]+\.[A-Za-z0-9_-]+` → `[REDACTED]`.
6. **Home directory:** the user's home path prefix → `~`.

Never logged at any level: transcript text, prompts, LLM responses, file contents, request or response bodies. Allowed: provider name, model id, endpoint host, HTTP status, byte counts, durations, word counts, error codes.

### 11.3 No telemetry

VoxClip sends no analytics, crash reports or usage pings. The only network requests are the ones the user's choices cause: transcription with ElevenLabs, LLM connectors, model downloads, the update check and publishing. About → "What leaves this device" lists them.

### 11.4 Secrets

- macOS: Keychain generic passwords, service `com.voxconvo.voxclip`, accounts `elevenlabs-api-key`, `llm-api-key-anthropic`, `llm-api-key-openai`, `llm-api-key-xai`, `llm-api-key-gemini`, and in M2 `voxconvo-session`. Account names use only `[a-z0-9-]` so they are valid Windows file names. `kSecAttrAccessibleAfterFirstUnlock`, login keychain (Developer ID apps need no access-group entitlement).
- Windows: DPAPI `ProtectedData.Protect(bytes, entropy: UTF-8 "com.voxconvo.voxclip", DataProtectionScope.CurrentUser)`, written atomically to `<data>\Secrets\<account>.bin`, same account names.
- Writing an empty value deletes the item. Stored keys are never displayed again; the field placeholder reads "Saved in the Keychain; paste to replace" (macOS) or "Saved for your Windows account; paste to replace" (Windows).
- Keys never appear in project files, settings files, logs, URLs or crash output. Gemini's key goes in the `x-goog-api-key` header.
- CLI connectors (Claude Code, Codex) own their sign-in. VoxClip never reads, copies or stores their tokens or config files; it only runs the user's installed, unmodified binaries.

## 13. Update checks

### 13.1 macOS: GitHub Releases API

- Request: `GET https://api.github.com/repos/Siim/voxclip/releases/latest` with `Accept: application/vnd.github+json`, `X-GitHub-Api-Version: 2022-11-28`, `User-Agent: VoxClip/<version> (macOS)`. No token. Timeout 10 s.
- When: 10 s after launch if "Check for updates automatically" is on (default on) and the last check was more than 24 hours ago; and on **VoxClip → Check for Updates…**. Results are cached in settings (`update.lastCheckAt`, `update.latestVersion`, `update.htmlURL`).
- Parse `tag_name` (strip a leading `v`), `html_url`, and the asset named `VoxClip-macOS.dmg`. `/releases/latest` never returns drafts or pre-releases.
- Compare with Core `compareVersions`: split the numeric part on `.`, integer per part, missing parts are 0; a pre-release suffix (`-…`) sorts below the same numbers without one. Both platforms test it against `shared/fixtures/version/compare.json`.
- If newer: the app menu shows "Update Available: VoxClip {version}…" and the Welcome window shows the one-line callout "VoxClip {version} is available." [Download]. Clicking opens `html_url` in the default browser after checking that the host is `github.com`. No automatic download, no forced quit, no prompt during export. A manual check with no update says "VoxClip {version} is the latest version." Offline: silent for automatic checks; "Couldn't check for updates. You're offline." for manual ones.
- Sparkle 2 is a possible later upgrade; it would add nested code to sign (release.md).

### 13.2 Windows: Velopack

- `Program.Main` calls `VelopackApp.Build().Run()` as its first statement, before WinUI starts; it handles the install, update and uninstall hooks (the install hook registers the `.voxclip` association for the current user, the uninstall hook removes it).
- `new UpdateManager(new GithubSource("https://github.com/Siim/voxclip", accessToken: null, prerelease: false))` with **no explicit channel**: Velopack uses the channel the build was packed with (`win-x64` or `win-arm64`), so each architecture follows its own feed.
- When: 10 s after launch with the same 24-hour throttle and setting as macOS, and on Settings → About → "Check for updates".
- Flow: `CheckForUpdatesAsync()` → if an update exists, `DownloadUpdatesAsync()` in the background (delta packages when available) → InfoBar "VoxClip {version} is ready. Restart to update." [Restart now]. "Restart now" is disabled while an export, transcription or clip search runs ("Finish the current task first."). The explicit restart action holds an application-wide UI-thread gate against new windows, project navigation, native close and Settings entry. It commits the active Settings text fields, pauses Settings controls and new settings writes, and drains writes accepted before the pause. Only then does it prepare open editors through their final-save boundary, await pending autosaves and disk writes, flush settings, and call Velopack once. A settings save failure, invalid field, active Settings action, busy transcription, clip search or export, competing transition, failed project save or cancellation vetoes dispatch. A failed dispatch keeps windows open and resumes both editing and Settings. If the user ignores the update, `WaitExitThenApplyUpdates` applies it when VoxClip quits.
- Development builds (`UpdateManager.IsInstalled == false`) skip update checks.
