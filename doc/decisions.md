# VoxClip decision record

Short architecture decision records (ADRs). "Locked" decisions were fixed by the project lead on 2026-10-25 and are not reopened without a new ADR that supersedes them. "Refinement" decisions were added while writing the specs to make the locked ones implementable; each says which locked decision it builds on, and the lead confirms or replaces it.

To change a decision, add a new row that supersedes the old one (keep the old row, mark it "Superseded by ADR-…"), and update the affected specs in the same commit.

| ADR-023 | Project file: **one portable JSON `.voxclip` file** (same schema on both platforms) referencing source media by **absolute path plus a relative fallback**; caches in app support | Projects move between Macs and PCs; media is never duplicated; caches are disposable |
| ADR-024 | **Source word timings never change**; edits are a **cut set + corrections + an explicit clip range layer**, with **explicit segment kinds** (word, pause, range) | Restoring never compounds shifts; fixes VoxConvo's clip head/tail mismatch caused by inferring kinds from ids and rewriting cut flags |

| ADR-028 | CI on **GitHub Actions**: macOS runner (swift test + build), Windows runner (dotnet test + WinUI build), plus the .NET core tests on macOS. **Signed releases are produced locally** (Mac) and on the VM (Windows), not in CI, for now | No signing secrets in GitHub; CI still guards both platforms |

**ADR-012 status:** Superseded by ADR-029, accepted in principle on 2026-10-25.

**ADR-030 — Official Windows platform runtimes (accepted 2026-10-25).** Refines ADR-002 and ADR-011 and the dependency policy in AGENTS.md. The native, self-contained Windows app may include the unmodified official runtime binaries selected by the pinned Windows App SDK 2.5.1 package graph, including Windows AI MachineLearning 2.1.74. The exact resolved versions and licence sources are recorded in [the dependency notice audit](dependency-notices-audit.md). Their Microsoft redistribution terms and required third-party notices, including the supplied Intel notices, are a narrow platform-runtime exception; they do not permit unrelated proprietary dependencies, fonts, models, or application code. Build-only SDK tools are not part of this runtime allowance.

VoxClip source remains MIT. This exception does not impose Microsoft runtime restrictions on VoxClip source, dynamically linked FFmpeg, or other components with their own open-source rights. Keep the runtime binaries unmodified, ship their exact notices, and preserve the package terms' open-source and LGPL reverse-engineering exceptions. Internal development and maintainer preview testing may continue under the packages' development and test rights. Public Windows redistribution still requires the downstream agreement path and final payload notices described in [release section 3.7](release.md#37-windows-runtime-redistribution-gate-open); accepting this dependency policy does not mark those conditions complete.

| ADR-R22 | **Required-hardware macOS `h264_videotoolbox` bar acceptance** checks actual composed BGRA submitted to the writer against canonical RGB within ±3, and decoded Y, U and V each within ±1 of an independently calculated, half-up rounded BT.709 limited transform of that same BGRA at the same frame, PTS and pixel. The output must be H.264 High, 8-bit 4:2:0, MPEG limited range, and BT.709 primaries, transfer and matrix. A finite inverse BT.709 RGB check stays bounded to ±2 from decoded YUV. This supersedes only ADR-R21's macOS decoded-canonical-RGB ±3 clause; Windows software and hardware rules stay as written. | ADR-R21; architecture §§5.6, 6.6, 9.5 case 8 | The composed writer input is within 2 RGB codes of canonical across all 72 samples. The limited-range inverse amplifies one-code chroma differences, so a decoded-canonical-RGB bound would reject correct tagged hardware output. The paired input and decoded checks still detect composition, matrix, range and encoder drift. |

**ADR-R22 measurement (M3 Max hardware VideoToolbox, 2026-10-25).** The writer boundary observer samples after the shared `FrameCompositor` at frames 9, 15 and 30 (0.3, 0.5 and 1.0 s), all eight bars and three interior points per bar (72 pairs). The permanent observer is internal, read-only and absent by default; it retains only RGB values and PTS from successful video appends. Independently decoded YUV from that same export differs from the independently calculated BT.709 limited transform by a maximum of Y/U/V = 0/1/1. A companion export using the CLI case's source, identity plan and output settings provides that writer observation; the black-box CLI export is separately checked against the witness, with its own decoded pixels and format description. The CLI's submitted pixels are not directly observed. Both outputs passed all 72 positions locally. The decoded RGB comparison against inverse YUV uses ±2 for decoder conversion and rounding: the largest measured channel difference was 1.415, and one YUV code can represent more than one RGB code under the limited-range inverse. This is not a decoded-to-canonical tolerance. Hosted CI acceptance remains pending.
