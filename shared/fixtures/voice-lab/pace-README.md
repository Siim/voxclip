# Speech pace cases

`pace-cases.json` is generated by `python3 tools/fixtures/voice-lab/generate_pace.py`.
It is a separate `voxclip-voice-lab-pace-cases/1` contract; existing request and dialogue vectors stay unchanged.
All inputs are synthetic. Both platform suites replay every row through recording stub transports, using the existing dialogue discovery and synthetic response.

The 15 rows cover omitted/default pace, 0.8 and 1.15, both range boundaries, two-decimal half-up rounding, validation before rounding, and default/refused dialogue pace.
`canonicalJSON` pins the complete JSON body. `exactBytes` requires literal UTF-8 request equality for non-default TTS and dialogue. Default TTS keeps its original platform serialization and its existing JSON goldens; it adds no field or serialization change.
`receiptPace` records the effective rounded speed, including 1.0 when speed is omitted. The quote/review binds the caller's unrounded finite pace (nil and 1.0 are equivalent), so even distinct choices that round to the same speed require a new approval. Pricing stays per character.

The pure clamp maps NaN to 1.0 and infinities to the corresponding boundary. Provider validation never clamps: nonfinite/out-of-range pace is invalid input before quote or dispatch. Dialogue rejects every raw non-default pace, even when it would round to 1.0.
`provenance.pace` is an optional number in [0.7, 1.2]; new speech receipts/recipes record the effective pace. Older projects omit it and remain valid without migration.

Provider documentation checked read-only on 3 November 2026: TTS with timestamps accepts `voice_settings.speed`; voice-settings update documents default 1; the Text to Speech guide gives 0.7–1.2. Text to Dialogue's `ToDialogueSettingsResponseModel` lists stability, similarity and clone strength, not speed.
