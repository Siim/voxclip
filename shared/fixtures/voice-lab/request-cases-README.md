# Voice Lab request cases

`request-cases.json` is generated by `tools/fixtures/voice-lab/generate_requests.py` from synthetic inputs only. No real voice, key or recorded provider response is used. Running the generator twice must produce byte-identical output. `contract.json` has its own generator, `generate_contract.py`, and is not changed by this one.

## Synthetic WAV files

A sample or audio spec has `rate` and `frames`, and optionally `fill`, `count`, `junkBytes` and `mutation`. The file is a RIFF/WAVE container with a RIFF size equal to the file length minus eight, then these chunks:

1. When `junkBytes` is present, a `JUNK` chunk of that many zero bytes, plus a pad byte for an odd length.
2. A 16-byte `fmt ` chunk: format 1, one channel, `rate`, byte rate `rate × 2`, block align 2, 16 bits. `mutation: "stereo"` writes two channels and changes nothing else.
3. A `data` chunk of `frames` little-endian signed 16-bit samples, each equal to `fill` (default 0).

`count` (default 1) repeats the same file that many times in place. Tests build these bytes in memory; no binary fixture is tracked.

The JSON escapes every non-ASCII character, so precomposed and decomposed text stays visible in diffs. The cases use only characters whose White_Space and General Category values are stable across Unicode 13 to 16 (all were assigned by Unicode 7.0), so the Unicode data in each Core and in the generator's Python does not change the expected results.

## Request goldens

These cases implement §15 test 12 for the clone (§6.7), voice changer (§7.3) and text-to-speech (§8.5, alternative request) endpoints. `discovery` holds the replies a fake transport serves for `GET /v1/models`, `GET /v2/voices` and `GET /v1/user/subscription`. `voice123` is a premade stock voice.

Each `cases` row has `case`, `operation` (`createClone`, `textToSpeech` or `voiceChange`), `input` and the expected `request`.

A consumer works through these steps:
1. Fix the multipart boundary to `multipartBoundary`, using the Core's test-only hook. Production boundaries are random, in the same `voxclip-` plus 32 lowercase hex form on both Cores.
2. Discover models, voices and the subscription.
3. Prepare the input, approve the quote and dispatch it once through a recording fake transport.
4. Compare the single paid request with `request`:
   - **`method`, `path` and `query`.** `query` is a map, empty when the URL has no query string.
   - **`headers`.** Names are case-insensitive and values are compared exactly. `xi-api-key` must carry the test key and is written as `[REDACTED]`. A multipart `content-type` quotes the boundary on both Cores. Other headers, such as `User-Agent`, are not compared.
   - **`json`.** The body, parsed and compared as a JSON object.
   - **`multipart`.** Compared byte for byte, in three ways:
     - **Whole body.** `bodyLength` and `bodySha256` (lowercase hex) cover the entire body.
     - **Framing.** Each part is `--`, the boundary and CRLF; then each header line followed by CRLF; then CRLF, the part's bytes and CRLF. The body ends with `--`, the boundary, `--` and CRLF.
     - **Parts.** `multipart` lists the parts in send order. Each part has its exact `headers` lines, in order:
       - A text part has one `Content-Disposition` line and a `value`; its bytes are the UTF-8 value.
       - A file part has `Content-Disposition` followed by `Content-Type: audio/wav`, and `sha256`, the hash of its bytes.

     A whole-body difference is located by the per-part checks.

| Operation | `input` fields |
|---|---|
| `createClone` | `displayName`, `language`, `createdAt` (RFC 3339, with any offset and fraction), `removeBackgroundNoise`, `samples` |
| `textToSpeech` | `voiceId`, `modelId`, `language`, `text`, `seed`, and optional `previousText` and `nextText` |
| `voiceChange` | `voiceId`, `modelId`, `language`, `seed`, `cleanAudioOn`, `audio` |

The fake replies are as follows:
- **Clone.** `{"voice_id":"created123","requires_verification":false}`.
- **Text to speech.** 4,800 zero PCM bytes as `audio_base64`, with the whole sent text aligned as one character run from 0 to 0.05 seconds.
- **Voice changer.** 4,800 zero bytes as `application/octet-stream`.

Context follows §8.5. Unicode White_Space is removed at both ends of `previousText` and `nextText`. A trimmed text of at most 300 Unicode scalars is sent as it is. A longer one keeps its last 300 scalars (`previousText`) or its first 300 (`nextText`), and the cut is then adjusted in two steps:
1. **Word rule.** If the kept 300 scalars contain White_Space, a word split by the cut is dropped. White_Space beside the cut is kept.
2. **Clean cut.** The cut then moves until it splits no cluster. A cut before scalar *i* is clean when scalar *i* does not extend a cluster and scalar *i* − 1 is not U+200D ZWJ. Combining marks (General Category M), ZWJ and variation selectors (U+FE00 to U+FE0F, U+E0100 to U+E01EF) extend a cluster.
   - `nextText` keeps scalars [0, k). While the cut at k is not clean, k decreases, so a partial cluster is dropped back to and including its base.
   - `previousText` keeps [j, n). While the cut at j is not clean, j increases, so orphaned marks and joiners are dropped.

A field that is empty after this is omitted.

The word-rule cases include a kept previous text that starts with a space or U+3000, and a kept next text that ends with a space or U+2009. The clean-cut cases are:

| Case | Previous cut | Next cut |
|---|---|---|
| `tts_v3_japanese_scalar_cut` | Leaves the combining voiced sound mark U+3099 first, which is dropped | Clean |
| `tts_v3_thai_cluster_kept` | Just before ที่ (U+0E17, U+0E35, U+0E48), which is kept whole | Just after ที่, which is kept whole |
| `tts_v3_thai_cluster_split_after_base` | After the base of ที่, so its two marks are dropped | After the base of ที่, so the base is dropped |
| `tts_v3_thai_cluster_split_between_marks` | Between the marks of ที่, so the second mark is dropped | Between the marks of ที่, so the base and first mark are dropped |
| `tts_v3_emoji_split_after_zwj` | Just after a ZWJ in a couple-with-heart sequence, so the rest of the sequence is dropped | Just after a ZWJ, so the partial sequence is dropped |
| `tts_v3_emoji_split_before_zwj` | Just before a ZWJ, as above | Just before a ZWJ, as above |
| `tts_v3_estonian_marks_at_cut` | A hyphenated route; the cut leaves U+0308 first, which is dropped | The window has White_Space and no word is split, so a final decomposed ä stays |
| `tts_v3_estonian_vowel_cut` | Just before a decomposed ä, which is kept whole | Between o and U+0303, so the o is dropped |
| `tts_v3_clean_cut_after_word_rule` | No word is split, but U+0308 follows a space before the cut, so it is dropped | No word is split, but the window ends with a ZWJ, so the ZWJ and the letter before it are dropped |

U+200B and U+001F are not White_Space. `tts_v3_unbroken_long_word` keeps U+200B inside its 300-scalar cut, and its next text keeps a final U+001F that trimming must not remove.

`tts_v3_short_context_sent_as_trimmed` has texts of at most 300 scalars once trimmed, so neither step runs. Its previous text keeps a leading U+0308 and its next text a final ZWJ, both of which the clean-cut rule would drop at a cut.

## Quote mutations

Each `quoteMutations` row names a `base` case and one changed `field`. The consumer prepares and approves the base input, then dispatches the changed input with that approval.

A row with `allowed: false` must fail with no paid send. It fails with the consent error, unless the row has `error: "invalidInput"`. Such a row's changed input is itself invalid, so dispatch refuses it with `invalidInput` first. `clone_display_name_unit_separator` is that row: its name gains U+001F.

A row with `allowed: true` must send exactly once:
- A `same` row dispatches the base input unchanged.
- `clone_display_name_white_space_only` changes only White_Space that trimming removes, so the bound name stays the same.

| `field` | Change |
|---|---|
| `seed`, `previousText`, `nextText`, `cleanAudioOn`, `createdAt`, `language`, `displayName`, `removeBackgroundNoise` | Replace the input value with `value`. For a clone, `language` is the `labels` language. |
| `sampleByte` | Flip the lowest bit of the last byte of the sample at caller position `index`. |
| `sampleOrder` | Swap the samples at the two caller positions in `swap`. |
| `sampleRole` | Swap the roles of the samples at the two caller positions in `swap`. |
| `same` | No change |

## Clone inputs

`cloneInputs` checks that both Core services accept and refuse the same own-voice clone uploads (voice-lab §6.5 and §6.7, WAV only until spike S5). Each row has `case`, `valid` and `samples`, each sample with a `role` of `consentStatement` or `training`. A row may override `displayName`, `language` or `createdAt` from `cloneDefaults`. Consumers read the subscription first, prepare the clone with a passing consent policy, and expect success for a valid row. For an invalid row they expect `invalidInput`, with no paid send.

| Input | Rule |
|---|---|
| Display name | Trimmed of Unicode White_Space (the `whiteSpace` list) at both ends, then 1 to 60 Unicode scalars with no control character (General Category Cc: U+0000 to U+001F and U+007F to U+009F) anywhere. The trimmed name is sent and bound to the quote. Trimming runs first, so a line break or U+0085 at either end is removed, while one inside the name is refused. Format characters (Cf) stay: U+200B is a valid one-scalar name. |
| Language | `[a-z]{2,3}`, matched against the whole value |
| Created | Floored to whole seconds: 1970-01-01T00:00:00Z to 9999-12-31T23:59:59Z |
| Samples | 1 to 25 files, with exactly one `consentStatement` |
| Each file | At most 16 MiB, accepted by the conversion-input WAV parser (complete mono PCM16, 8–96 kHz), and lasting 5 to 30 seconds: `5 × rate ≤ frames ≤ 30 × rate` |
| Total | The sum of `frames ÷ rate`, in IEEE double arithmetic in caller order, from 10 to 240 seconds |

## White_Space

`whiteSpace` lists the 25 code points with the Unicode White_Space property (PropList.txt):
- U+0009 to U+000D
- U+0020, U+0085, U+00A0 and U+1680
- U+2000 to U+200A
- U+2028, U+2029, U+202F, U+205F and U+3000

Display names and §8.5 context are trimmed with exactly this set. Each Core checks its own predicate against the list over every Unicode scalar:
- **Mac:** Swift `Unicode.Scalar.Properties.isWhitespace`.
- **Windows:** .NET `Rune.IsWhiteSpace`, and `char.IsWhiteSpace`, which `string.Trim()` uses.

Two near-matches are not used, because neither equals the White_Space set:
- Foundation's `CharacterSet.whitespacesAndNewlines` also contains U+200B.
- Python's `str.isspace()` also accepts U+001C to U+001F.

Each Core also checks over every Unicode scalar that its control-character predicate is exactly U+0000 to U+001F and U+007F to U+009F. That set is General Category Cc, which the Unicode stability policy never changes:
- **Mac:** Swift `generalCategory == .control`.
- **Windows:** .NET `char.IsControl`, and `Rune.GetUnicodeCategory` returning `Control`.
