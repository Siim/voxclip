# Audio tag annotations

`audio-tag-cases.json` is generated by `tools/fixtures/voice-lab/generate_audio_tags.py`.
The ordered whitelist, estimates, tag-capable model IDs and Scribe event spellings
come from `shared/data/voice-audio-tags.json`; both platforms read that file.
The generator also refreshes the schema's whitelist enum from that source.

Request vectors cover v3/v4 inclusion and v2/unknown omission. The other vectors
cover dropping unsupported/out-of-range annotations, non-lexical QA events,
alignment with and without tag characters, normalized numbers/currency, duration
allowances, and optional-field round-trips. Expected word timings use a synthetic
10 ms character clock. Normalized substitutions take the union of their provider
word times; the ordered word diff preserves matching anchors.

`dialogueFallbacks` carries null original alignment and validated normalized
arrays for both number and currency expansion, on a 0.5 ms clock. Its segment end
is the raw provider character count, deliberately longer than the typed text.
Mac's stubbed provider replay validates that bound before mapping to typed words.

macOS replays all sections. Windows replays optional-field decode, validation and
preservation only; the behavior/UI twin is explicitly owed in its CONTRACTS.
The older dialogue fixture's `alignment_null` case predates the macOS fallback:
macOS now expects success when its valid normalized alignment is present; Windows
retains the older expectation until its behavior twin lands. Other faults keep
their original fault precedence. Both alignments null still stops.
