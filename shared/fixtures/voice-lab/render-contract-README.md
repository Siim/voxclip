# Voice Lab render contract fixtures

`tools/fixtures/voice-lab/generate_render.py` creates the additive `*-render-v3.voxclip` projects and `render-cases.json` from the source-preserving v2 project fixtures. Run it from any directory with Python 3. Both Core suites consume these generated files; no provider response, paid asset or binary media is included. The provider-service `README.md`, `contract.json` and the rewrite prompt are maintained separately.

`passage` is equal-duration source video with a selected aligned TTS candidate, a required patch room-tone run and two candidates with distinct trims, seeds and word timing. `full-take` is an equal-duration, two-chunk group with explicit request IDs and assembled frame spans. `voice-changer-half` tests the 50% persistence boundary without TTS QA fields. `disclosure-at-30` and `disclosure-above-30` test the strict all-AI threshold.

`touching` contains two selected passages meeting at one shared 20-sample synth seam. `one-sample-gap` retains one source sample between them and requires preparation to reject overlapping windows; that sample must never be swallowed. `clipped-seam` begins its clip at the internal synth seam and requires a typed handle refusal. `render-cases.json` also records a half-sample JS rounding vector and a planner-only 1100-for-1000 mapping case that source-video render capability rejects. These are synthetic clock and validation vectors, not accepted render outputs.

The 13 render cases include three unity-duration baseline regressions: `unity-binary64-residual-eight` is the 44.1 kHz source / 24 kHz asset recipe over [1.5, 2.503] s with 24,080 content frames and `outDuration = 1.0033333333333334`, coincidentally on the source grid; `unity-binary64-residual-nine` is its nine-frame neighbour. Both must pass the binary64 baseline. `unity-legacy-source-grid-only` fails that baseline and passes only the permitted source-grid fallback. Both Core validator suites replay them.

Validate with `python3 tools/schemas/validate.py shared/fixtures/voice-lab/*-render-v3.voxclip`. Core tests add malformed public input, candidate transition, stale request, enum, immutability and invalid policy checks around these shared values.

`tools/fixtures/voice-lab/generate_render_recorded.py` derives three projects with the user's own microphone take (a `recorded` segment, voice-lab.md §8.13) from the passage, touching and lip-sync projects: `recorded-render-v3.voxclip` (one recorded passage, no voice references), `recorded-lipsync-render-v3.voxclip` (the same take lip-synced) and `recorded-beside-tts-render-v3.voxclip` (a cloned passage touching a recorded one). `recorded-take-cases.json` (`voxclip-voice-lab-recorded-take-cases/1`, 17 cases) gives each project's disclosure (only lip sync on an own take is AI), sidecar kinds and captions, accept-all without a voice reference, and the refusal of each changed recorded recipe. The Windows Core and Media suites replay it; the schema check covers the three projects.
