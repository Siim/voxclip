# Fitted-asset byte contract — §8.9.3 / §15 test 19

`fitted-asset-cases.json` is generated by
`python3 tools/voice-lab/generate_fitted_assets.py`. Regeneration must be byte-identical.
The inputs are synthetic integer patterns, not a person's speech or provider output.
The Mac Media suite replays every input and expected SHA-256. Windows Media must
replay the same vectors when its fitted writer lands; Windows production code is
not changed by this package. Do not weaken the hashes to accommodate a different
encoder or join implementation.

## Inputs

Each paid asset has 21,600 frames at 24 kHz. For frame `i` and channel `c`, start
with the signed Q15 integer `(17*i + 13*c) % 127 - 63`. Add 18,000 in the half-open
ranges `[2300,2600)`, `[4800,6000)`, `[14400,15600)` and `[19000,19300)`. These
include two voiced spans and markers across both seam handles. Divide by 32,768
to obtain the exact normalized value. Store it in the case's sample format,
interleaved by channel. Integer PCM scales by `2^(bits-1)`; IEEE float stores that
normalized value. The trim is `[2400,19200)`. The source grid is 48 kHz; its
20 ms gap seams need 240 paid frames on each side. Window bounds, pads and edits
are explicit in each case. `borrowed-window` widens the source start to 2.48 s.

## Output

The fitted order is incoming handle, incoming silence pad, edited trim,
outgoing silence pad, outgoing handle. A padded seam continues digital silence
through its handle. Otherwise its handle is copied from the paid frames.
Removal drops `[start,start+count)`; insertion repeats that span once. Each jump
has one 480-frame equal-power join centred at the jump: 240 frames before and
240 after. Join frame `j` uses `u=j/479`, separately computes
`left*cos(pi*u/2)` and `right*sin(pi*u/2)` in binary64, then adds them. Integer
encoding rounds half to even and saturates to the full signed PCM range; float
encoding rounds only when storing float32. There is no dither. Every other frame
is copied as bytes. Room tone and level gain are not baked into this file.

WAVs have a canonical 44-byte little-endian RIFF header: one 16-byte `fmt `
chunk, format 1 for integer PCM or 3 for IEEE float, followed by `data`. Byte
rate, block alignment and bit depth match the case. An odd data byte count has
one zero RIFF pad byte, included in the RIFF size but not the data size. Metadata
chunks and timestamps are absent. The whole WAV is hashed. An unchanged plan
uses the paid WAV directly, including its original trims and SHA-256.

Recipes use fit factor 1. Their trim frame difference is `outputFrames` under
JavaScript half-up rounding. `outDuration` is the binary64 subtraction
`windowEnd - windowStart`, followed by addition of `residualSeconds` only for a
changed-duration plan. Chunks retain the paid asset ID, paid SHA-256, request ID
and seed, but their assembled bounds use the fitted grid between its handles.
Accept lists both asset records in one project transaction; scratch generation
does not list an incomplete or unverified asset.

The native Mac test additionally passes `balanced-edits` through v3 validation,
edited WAV export and decoded MP4, checking the two body markers and both seam
markers. Existing passage, full-take, touching and non-unity refusal tests stay
separate regression gates.
