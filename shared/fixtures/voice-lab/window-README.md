# Voice Lab window geometry vectors

`tools/fixtures/voice-lab/generate_window.py` is an independent standard-library Python reference for the patch geometry in `doc/spec/voice-lab.md` §8.3-§8.10 and §10.5. It writes `window-cases.json`; running it twice gives byte-identical output. Both Core suites (`VoiceLabWindowTests`) consume every case and check `caseCount`. The schema id is `voxclip-voice-lab-window-cases/3`. Version 3 adds the replacements already in a take (`segments` in every window input), the `overlapsReplacement` and `adjacentReplacement` refusals with their `segmentId`, `RMS_FRAME` among the constants and the multi-segment fuzz, so a reader of version 2 must not accept the file. The file holds short synthetic transcripts and 10 ms envelopes as `[level, frames]` runs of exact binary32 values. It contains no provider output, paid asset or media.

All second-to-sample conversions use editing §4.1 jsRound on the source grid. A frame `i` covers samples `[i·F, (i+1)·F)` with `F = max(1, jsRound(rate × RMS_FRAME))` and `RMS_FRAME = 0.010`, as in `AudioEnvelopeBuilder`. Gaps are compared in samples, so `gap-exactly-min` is exactly `jsRound(0.12 × rate)` samples and `gap-one-sample-below-min` is one sample less.

- `window`: §8.4 replace windows, placed for the render scope the output plan uses: `clipId`, or the full take when it is null. Each input carries the take as `VoiceLabOutputPlanner` sees it: `sampleRate`, `durationSeconds` (`media.source.durationSeconds`), every transcript item in order, `edits` with the cut words and pauses, the pause threshold and keep, and the clips, and `segments`, the replacements already in the project (see below). The items follow the project transcript rule (finite times, `0 ≤ start < end`, starts in order, unique IDs); a take that breaks it fails with `invalidInput`. Kept source comes from a model of the editing plan (`detectPauses`, `clipTimes`, `buildSegments` and `buildEditPlan`, editing §5.7, §7.2 and §7.3) with the words and pauses inside every replacement and the window dropped and every synth range removed, as the output planner builds it, so nested items, cut pauses, a clip's head and tail and other replacements count. The left search checks the gap before `a`, then `a−1` to `a−3`; the right search mirrors it, and the trailing silence is an ordinary gap. A gap runs from the latest end of the items before it to the earliest start of the items after it. A bridge never includes a cut word, a word outside the clip, a replaced item or a non-word item. A gap seam sits at sample `i·F + ceil(F/2)` of its quietest whole frame whose centred `SEAM_FADE` lies wholly in kept source, which also keeps it inside the take, and clear of each replacement's outer fade halves. Ties go to the frame nearest the gap centre, then the earlier one. A gap with no such frame is skipped and the search goes on. Each search measures kept source against the widest window the other side could reach, through a bridge or by absorbing cut items at a take edge, because a cut's reach depends on which items the window drops; the exact window is checked after placement. Otherwise the seam is hard at `a.start − min(0.03, max(0, gapBefore)/2)` (mirrored on the right); overlapping items leave no silence, so the reach is clamped at zero, as editing §7.3 clamps a cut's reach. A replacement R that ends no later than the end of that gap moves its start to `(jsRound(R.end × rate) + ceil(N_R/2) + floor(N_hard/2)) / rate` when that is later, and one that starts after `b` mirrors it with `floor(N_R/2) + ceil(N_hard/2)`, so the hard seam leaves room for both outer halves whenever the silence holds them. The take ends on sample `jsRound(durationSeconds × rate)`, so the last item's trailing gap runs to `durationSeconds`, not to `totalSamples / rate`. Take edges count kept and replaced items only. When no kept or replaced item lies before the window's first word, the window starts at sample 0 with seam `none` and absorbs any earlier cut items; when none lies after its last word, it ends at exactly `durationSeconds` with seam `none`. This holds whatever the gap or the fade. In a clip scope the window reaches a take edge only when the clip's range (`clipTimes`) does, in seconds, because the output plan refuses a replacement outside it; a clip starting 5 µs into the take keeps sample 0 but not time 0. A hard seam whose fade would still cross a take edge fails with `seamFadeOutsideTake`. After placement the window holds its passage and bridges and may absorb cut items, events and unlabeled speech, such as an event that starts with the passage or one nested in its last word; a kept word inside it outside the passage and bridges fails with `windowCrossesWord`. The kept source beside each seam with a fade must hold the fade's outer half, `floor(N/2)` samples before an incoming seam and `ceil(N/2)` after an outgoing one; otherwise the window fails with `seamFadeCrossesCut` and its `incoming`, `needed` and `available` samples. The window must also hold the inner halves of both fades, the validator's `overlappingFades` condition `(Nin − ⌊Nin/2⌋) + ⌊Nout/2⌋ ≤ endSample − startSample`; a shorter window fails with `windowTooShort` and its `needed` and `available` samples, and nothing bridges it automatically. The 44.1 kHz durations 1235/600 (rounds down) and 1237/600 (rounds up), a last word 3 ms before the off-grid end, an FFmpeg-style `n·(1/48000)` duration, a whole take and a first word that rounds to sample 0 pin both edges. Cases cover both outcomes at each edge, cut reach on each side, cut fillers absorbed at either take edge, a hard seam inside a cut's reach after a kept word, a window exactly as long as its two inner half fades and one 48 samples shorter, a passage nested in a cut event, the widest-window assumption on each side through a bridge and through an absorbed cut item, nested items, cut pauses, clip scopes, §15 test 3, 44.1 kHz odd frames, insertion and the typed errors. Where `floor(N/2)` and `ceil(N/2)` differ, named cases pin each half: at 22.05 kHz (gap fade 441) a cut edge exactly 220 samples before or 221 after a candidate's seam, and one sample closer; at 44.1 kHz a hard seam 265 and 264 samples before the take end, and windows of 705 samples that hold `441 + 264` but not `265 + 441`, and one of 704. Further cases pin the left hard seam's clamp at zero beside a simultaneous event, the absorbed event at each end, a lost kept word, and both transcript rules.
- Replacements (`segments`): each is `{id, enabled, window}`, where `window` is the `place` result it was placed on, in its own scope, before the case's window. Both suites build it as a one-word passage recipe with the case's `roomTone`, so a case that holds replacements always carries the take's room tone, even when its window is refused. The scope's replacements are the enabled ones, and in a clip scope those overlapping the clip's range; one that crosses the range, has no synth samples or overlaps another fails with `invalidInput`. Their fades come from the window's seams (a recipe's seams in the Cores). A window that overlaps one, in seconds, fails with `overlapsReplacement` and its `segmentId`. On the pieces the output plan builds with the window as one more replacement, a window that touches one or leaves one kept piece between them shorter than `ceil(Nout/2) + floor(Nin/2)` fails with `adjacentReplacement`. Every replacement's seams are then checked as the window's are, both with and without the window: an outer fade half in the kept source right beside its seam, and room for both halves in a single kept piece between two replacements. A check that holds without the window and fails with it is the window's doing (its dropped items can lengthen a cut's reach) and fails with `adjacentReplacement`. A check that already fails without it, after an edit made once the replacement was accepted, is judged by prepare's own rule: the neighbouring output piece is source and holds the outer half, and the kept source between two replacements, the window included, holds both. If that rule holds with the window the window is accepted; if it holds only without, the window fails with `adjacentReplacement`; if it fails without the window too, the take did not render before it, and the window fails with `invalidInput` and that replacement's `segmentId`. The first failure is reported in this order: the window's own samples (`invalidInput`), `overlapsReplacement`, `windowCrossesWord`, `seamFadeOutsideTake`, the incoming side (`adjacentReplacement` or `invalidInput` with the neighbour's `segmentId`, then `seamFadeCrossesCut`), the outgoing side, `windowTooShort`, then each replacement in source order. A case's `edits` and `segments` are the final state, so they may hold edits made after the replacements were placed: more cut words and pauses, and replacements enabled again. Cases cover the next sentence after a replacement, a disabled replacement and one outside the clip (neither changes the window), a replacement crossing the clip, the passage inside a replacement, a replacement blocking the take edge, touching on each side, a kept piece too short for both fades on each side, hard seams that clear a replacement's gap or hard fade on each side (also at 44.1 kHz, where the odd hard fade pins which half each side keeps), a window that closes the kept piece between two other replacements, a pause cut after acceptance under a replacement's seam (a window elsewhere is accepted, the next sentence gets a hard seam after the cut, and a gap seam whose fade would overlap the replacement's across the cut fails with `adjacentReplacement`), a window that drops the item keeping a pause's breath and so moves the pause cut into a far replacement's fade (`adjacentReplacement`), cut words that leave a 5 ms sliver after a replacement (`invalidInput` naming it) and a window over those words that restores kept source, and two replacements already too close for both fades (`invalidInput` naming the first).
- `propertyCases` and `propertyFuzz`: the property test of the invariant that every window `place` returns validates and prepares in its render scope. The generator models the transcript rule, `VoiceLabProject.validate`'s replace-range, seam, edge and overlap rules and prepare's output pieces and neighbour rules (`VoiceLabOutputPlanner.build`, `validateSelectedSeams`) for every replacement in the take, sharing only the editing model with `place`. It fuzzes 20,000 random takes from LCG seed 20261027 (Knuth's MMIX constants) at 44.1 and 48 kHz, with touching, short and long gaps, connected speech, nested and overlapping items, events, cut words and pauses, clip scopes, words at the take edges and off-grid durations. No accepted window may fail the model, and every refusal must be `seamFadeCrossesCut`, `seamFadeOutsideTake`, `windowCrossesWord` or `windowTooShort`; `propertyFuzz` records the seed and the counts. Every 66th case, 300 in all, is committed one per line with its expected output. Every window and property case carries `roomTone`, the room tone `VoiceLabRoomToneSelection` must pick from its take for an accepted window, or null. Both Core suites replay every case and validate and prepare every accepted window in the case's scope: with room tone they select it and build a one-word passage recipe, and without it they build a voice-changer recipe, which needs none. Every take in the fuzz holds a silence of at least 0.6 s, so every accepted property case is built as a passage.
- `multiSegmentCases` and `multiSegmentFuzz`: the same invariant beside replacements. Each of 20,000 takes from LCG seed 20261028 first receives one or two replacements that `place` itself puts there: usually the words just before or after the passage, sometimes anywhere, mostly enabled and in the passage's scope, some disabled or placed for the full take. Half the takes then receive edits as an editor makes them after acceptance: cutting the item just before or after a replacement, cutting a pause its seam lies in, and enabling a disabled replacement again. Every placement must be refused with a typed error, or render with every replacement already in the take. `invalidInput` without a `segmentId` comes only from a full-take replacement that crosses the clip or a re-enabled one that overlaps another; with a `segmentId` it comes only from a take that fails the model without the window. `multiSegmentFuzz` records the counts, including the windows accepted directly beside a replacement and after later edits. Every 133rd case, 150 in all, is committed with its `segments` and room tone, and both Core suites build every replacement and validate and prepare the project with the accepted window added.
- `handles` and `trimHandles`: §10.5 minimum handles with the render validator's arithmetic: `floor(N/2)` before an incoming trim, `ceil(N/2)` after an outgoing one, the four-ULP integral rule, and zero source handle at a synth-to-synth seam. `rawFrames` is informational. `trimHandles` checks asset frames before `trimStart` and after `trimEnd` (`insufficientHandle`).
- `alignment`: the §8.8 loop with the Unicode White_Space list (U+0085 separates words; U+FEFF and U+200B do not). Each derived and expected token is NFC-normalised before `normalizeForMatch`, which editing §4.7 defines on NFC text, and the results are compared ordinally. Word text stays as the provider sent it. A token holding a noncharacter (U+FDD0–U+FDEF, or U+xFFFE or U+xFFFF in any plane) makes the alignment mismatch on all three implementations, before NFC; on Windows a lone surrogate does too, which the Windows suite tests on its own because the shared JSON cannot carry one. Cases cover §15 test 5, mismatch, null or malformed alignment, Estonian punctuation and case, NFD against NFC in both directions, and noncharacters in the provider characters, the patch text, or both. Every word is `synthetic: true`.
- `trim` and `relativeWords`: §8.7 item 1 with alignment, or, when alignment is null, the first to the last envelope frame above −45 dBFS (`VOICED_FRAME_LEVEL`, binary32 neighbours included). Both widen by `TTS_TRIM_LEAD` before and `TTS_TRIM_TAIL` after, clamped to the asset at either end. Recipe word times are checked as the v3 validator checks them.
- `roomTone`: §8.7 item 3, the lowest summed power over 50 whole frames inside a gap of at least 0.5 s between items of any kind, with take edges and ties. With no qualifying gap the result is `roomToneUnavailable`: there is no fallback run, and the UI offers Clean audio instead. A run must hold both 50 whole frames and `jsRound(0.5 × rate)` samples; it returns the second. At 22.05 kHz the frames are longer (11050 against 11025 samples) and at 11.025 kHz the samples are (5513 against 5500). At each rate, one gap fits exactly and one is a single sample short, so the short case fails only through the term that wins at its rate.
