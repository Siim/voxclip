# Voice Lab Core contract fixtures

`word-diff-cases.json` and `length-budget-cases.json` are generated by
`generate_word_diff.py` and `generate_length_budget.py`. Both Core suites replay
every case, including whole-item widening/corrections, nonword barriers and
explicit absorption, complete-window pricing, and fit-meter quotes without window-search bridges.
Only `token-limit-source`, `token-limit-newText`, and `token-limit-inclusive`
use compact repetition recipes. `sourceRepeat` supplies `token`, `count`,
`idPrefix`, and `timingStep` in seconds: item `i` has ID `idPrefix + i`, start
`i * timingStep`, and end `start + timingStep / 2`. `newTextRepeat` joins `count`
copies of `token` with single spaces. `expected.repeatedOps` independently
specifies the ordered operation kind, source/new tokens, ID prefix and count;
neither suite asks the production diff to construct expectations. All 2,000
ordered operations, empty hunks, budget and summary are asserted; both 2,001
refusals pin side/count/limit. Every other vector remains literal. Change the
generators, not the JSON; all inputs are synthetic and offline.

`render-cases.json` is generated by `generate_render.py`. Its unity cases retain
both binary64 residual baselines and the legacy source-grid-only baseline.
`unity-inconsistent-alternate` builds a project with a valid selected recipe and
an unrejected alternate whose content exceeds its output duration by four asset
frames. Both project and render validation must refuse it with `invalidSegment`;
marking the alternate rejected restores acceptance.

The nonunity vectors `nonunity-inconsistent-alternate` and
`nonunity-consistent-alternate` use a valid selected unity recipe at an 8 kHz
source and a 96 kHz, 21.5-second asset. Their alternate trims are [0.5, 20.5]
and their declared duration is 20 seconds. Stretch 1.0000009 has an 18 µs
duration error and fails `invalidSegment` while unselected; 1.0000004 has an
8 µs error and validates before and after selection. Both pass the existing
ratio and `STRETCH_OK` checks. This is validation coverage, not permission to
render nonunity audio: both Media implementations still refuse it (ADR-R30).

The audio-math generator produces identical bytes with NumPy 2.2.5 and 2.5.4 on
Apple silicon: SHA-256 `8ff014b4949f7476a0640ad94f455115f634d3efd1f6eb1e736d741bd34d7a34`.
On the hosted Ubuntu runner, libm (`log10`, `tan`, `pow`) and NumPy's SIMD sums
change the last bits of some floats (up to about 1e-13 in accumulated loudness). CI
therefore checks `audio-math-cases.json` with `tools/fixtures/voice-lab/check_drift.py`
after the generators: identical structure, strings, booleans and integers, and floats
within a relative 1e-10 and an absolute 1e-12. Every other output must match byte for
byte. Locally, run `python tools/fixtures/voice-lab/check_drift.py` before the diff.

`contract.json` is the shared Mac and Windows behavioral contract for the first Core service path. `tools/fixtures/voice-lab/generate_contract.py` writes it (Python 3, standard library only, byte-identical on every run); change the generator, never the JSON. The values are synthetic and contain no real voice sample or provider asset. Tests construct mocked discovery and generation responses from these cases; no live request is needed.

`voiceChoices` gives the only stock categories: `premade`, and owner-created `generated`. `own` means a cloned voice with matching active consent, speaker match and completed provider verification. Other categories are denied before a paid request. `quoteMutations` changes one reviewed input after preparation; every changed case must cause zero paid sends. The `same` case permits one send. A quote includes operation, caller request ID, provider, region, endpoint, model, voice choice, language, consent identity and state, text or audio SHA-256, and the displayed estimate. Rewrite quotes also include scope, full timed source words, instruction, language, connector, model, prompt/schema identity and the length budget (`targetSeconds`, `minChars` and `maxChars`, voice-lab §8.9.1), so `rewriteMutations` has 11 rows: one per bound field and `same`. Quotes are service-issued, instance-scoped and single use. They are consumed synchronously before the first possible paid dispatch. Discovery and preparation are separate; preparation performs no network I/O.

`replay` counts only billable sends, after discovery. A failed or ambiguous send needs a fresh quote and affirmative approval, including for another candidate or chunk. A cancellation before dispatch can be quoted again; cancellation after dispatch may have billed and is never automatically retried. `discovery` sets malformed duplicate and pagination outcomes. `audio` uses 2,400 synthetic samples for valid PCM cases. Header-like sample bytes alone are valid; a structurally valid encoded container or two valid MP3 frames or declared encoded content type is rejected. Conversion input is a complete mono PCM16 WAV (8–96 kHz, at most 290 seconds), and its exact bytes are bound to the quote. Timestamped TTS sends `language_code` except for `eleven_multilingual_v2`, which uses documented auto-detection. The quote exposes `explicit(language)` or `autoDetected(expected: language)` so callers can review the mode. Voice conversion validates language against the selected model and marks auto-detection; its endpoint has no `language_code` input.

`conversionInputs` is an additive version 1 table of synthetic RIFF/WAVE acceptance cases. Each row has `case` and `valid`; `rate` defaults to 24,000 Hz and `frames` to 2,400 mono PCM16 samples. `ancillary: true` adds odd and even `JUNK`, `LIST` and `cue ` chunks around `fmt ` and `data`; `slice: true` supplies identical bytes from a `Data` value with a nonzero start index on Mac. Optional `mutation` names the single header, chunk or PCM change to generate. The table covers exact RIFF boundaries, bounded chunk payloads and padding, duplicate or missing format/data, PCM format fields, both duration boundaries and invalid samples. Tests construct bytes in memory; no large binary fixture is tracked. For every invalid row, preparation must reject before any paid send. For valid rows, preparation performs no network work after explicit discovery and one approved conversion sends the exact supplied bytes once.

The generator starts with a RIFF/WAVE header, one `fmt ` chunk (format 1, one channel, rate from `rate`, byte rate `rate × 2`, block align 2, 16 bits) and one `data` chunk of `frames × 2` zero bytes. Each chunk has a little-endian 32-bit payload length and an extra pad byte for odd payloads. The RIFF size is the actual file length minus eight. `ancillary` inserts `JUNK` payload `[1,2,3]` before `fmt `, `LIST` payload `[4,5]` between `fmt ` and `data`, and `cue ` payload `[6]` after `data`. `slice` changes only the Mac `Data` view, not the file bytes.

| `mutation` | Change to the generated file |
|---|---|
| `fmt18`, `dataBeforeFmt` | Append zero `cbSize` to `fmt `, or place `data` before `fmt `. |
| `riffShort`, `riffLong`, `truncateFile` | Change the RIFF size by −1 or +1, or remove the last physical byte without changing the declaration. |
| `truncatedChunk`, `overflowChunk`, `missingPad` | Declare `data` two bytes longer; declare `fmt ` length `0xffffffff`; or append a one-byte `JUNK` chunk without its required pad, with the RIFF size matching physical length. |
| `duplicateFmt`, `duplicateData`, `missingFmt`, `missingData` | Duplicate or omit the named chunk. |
| `floatFormat`, `stereo`, `pcm8` | Set format tag 3, channel count 2, or bits per sample 8. |
| `badAlign`, `badByteRate`, `oddPayload` | Set block align 1, add 1 to byte rate, or append one byte to `data`. |

Rows without a mutation vary `rate` or `frames` to test sample rate and duration limits. The 20 ms threshold uses ceiling of `rate / 50` frames, including nonround rates. The 290 s threshold uses `rate × 290` frames.

`continuity-cases.json` pins the §7.2 extraction placement rule through production Swift `bufferFirstSample` and C# `SourceFrame`: **60 cases**, SHA-256 `6273ac27cb2f5573452907d4a8e285c62c7fd9c79ee0dc3be68cf4ed3c5f0d27`. Generate it with `python3 tools/fixtures/voice-lab/generate_continuity.py`; two consecutive runs are byte-identical. The Linux-portable oracle uses binary64 in DecodeSession's exact evaluation order: `seconds = float(value) * (float(numerator) / float(denominator))`, `position = (seconds - origin) * float(rate)`, `tick = float(rate) * float(numerator) / float(denominator)` left to right, and `floor(position + 0.5)`. Half-sample ties follow that evaluation, not exact rational arithmetic. `timestamp` is null for missing time; every row supplies an `origin`, including 1.4 s and quarter-millisecond cases. Production retains the Mac asset-timeline origin 0.0 and Windows DecodeSession origin. `previousEnd` is null until the first frame is placed; `nextSample` is the requested output cursor and never anchors placement. `sampleCount` bounds the expected skipped overlap. A gap row includes both its placed `firstSample` and `rangeOutsideMedia`, so placement and decoder coverage are independently pinned. Cases include the 101/96,000 tie and 100/102 neighbors, exactly representable and negative ties, 1/1,000 at 2 kHz with fractional origins, first versus anchored 4799.4-at-4800, negative preroll, missing timestamps, strict binary64 one-sample/one-tick boundaries and accumulated 40-sample gaps. Swift also replays every case through the actual PCM accumulator. `check_drift.py` requires these bytes to match exactly; no float tolerance applies.
