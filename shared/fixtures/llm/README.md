# Shared LLM golden fixtures

Generated by `tools/fixtures/llm`, VoxClip's own MIT implementation written from
`doc/spec/ai.md`, independent of either native app. Do not edit JSON by hand.

```sh
npm --prefix tools/fixtures/llm run generate
npm --prefix tools/fixtures/llm run check
```

## Files and format

| `finalize-clips.json` | 29 | C1–C3, invalid numbers, ranking, UTF-16, exact length bounds for every preset |
| `extensions.json` | 26 | All S1/M1/N1/W1 vectors, snapping integration, cuts, window budgets, entry preparation, strings |
| `tighten-verifier.json` | 16 | T1–T8 plus duplicates, kinds, no-ops, Unicode, punctuation and review thresholds |
| `clip-finder-requests.json` | 30 | Every preset, with/without instructions, single/multiple windows; 252 connector renderings |
| `ai-tighten-requests.json` | 20 | All strengths, instructions, windows, sparse indices; 180 connector renderings |
| `connector-requests.json` | 37 | Connection tests, capability branches, CLI escaping/flags, Apple mapping; 37 renderings |
| `voice-rewrite-requests.json` | 7 | Voice Lab rewrite (voice-lab §8.9.1): passage and full take, with and without a request, six budgets including `minChars` = `maxChars`, a decomposed source; each with the quote's estimate and preflight |
| `patch-rewrite-requests.json` | 5 | Voice Lab Fix with AI (voice-lab §8.1): the line ranges and instruction, equal `minChars` and `maxChars`, a trimmed instruction, F1, sparse indices, decomposed Estonian text; each with the quote's estimate and preflight |
| `cli-replies.json` | 86 | Claude and Codex CLI transport envelopes (ai.md §4.5, §6.8–§6.10): stops, structured/text replies, depth and strict-JSON bounds, signed 64-bit integer ranking and usage, category-ordered failures, first app-server response selection, optional fields, line endings and stderr selection |

The CLI rows include Claude output-token ties (UTF-8 ordinal keys, independent of JSON order), `output_tokens`, malformed envelopes with signed-out stderr, malformed envelope field types, and exact-zero number tokens of 1,024 and 1,025 bytes in both replies and envelopes. Optional envelope fields of the wrong type are absent, and integral float status and usage fields are accepted. Integer ranking and recorded usage cover counts above Int32, 2^53, -1, -2^63, the largest binary64 below 2^63 and out-of-range values, including a decimal that rounds to the excluded upper bound. Four conflicting marker/status rows pin Claude's first matching category in list order, including integral float status. Codex exec and app-server rows cover wrong event and metadata types, wide and absent usage, CRLF, a trailing CR, raw U+2028 inside a JSON string, and a leading BOM. The stderr rows cover leading blank lines, empty and whitespace-only stderr, CRLF, internal CR and U+2028, and markers on selected or ignored second lines for malformed Claude envelopes, Claude errors and Codex errors. Both connector suites replay every row.

App-server duplicate-id rows pin both valid-then-malformed and malformed-then-valid order: the first id-2 response decides, with curated fallback for a malformed first result. Another row accepts `2.0` after ignoring fractional/out-of-range ids and ignores a later duplicate id 2. The wrong-optional-fields row isolates metadata parsing in that first response.

Current `cli-replies.json` SHA-256: `04444fc06a9143a28798390a16c559adde066686e70355b9b4bf6fc728d33401`.

Each UTF-8 file has stable insertion-order keys, LF line endings and one trailing
newline. Its envelope is:

```jsonc
{
  "schema": "voxclip-llm-fixtures/1",
  "id": "format-transcript", // filename without .json
  "origin": "voxclip",
  "sources": { "shared/prompts/clip-finder.json": "<sha256>", "…": "…" },
  "cases": [{ "id": "F1", "kind": "format-transcript", "origin": "voxclip",
    "source": "doc/spec/ai.md §13.2", "input": { "entries": [] }, "expected": {} }]
}
```

`source`, `origin` and optional `notes` are provenance, not assertions. The
`sources` hashes are SHA-256 of UTF-8 source files with CRLF normalized to LF
(a Voice Lab request file lists only its own prompt),
detecting prompt/catalog drift without depending on Windows checkout settings.
The scoped `.gitattributes` pins the goldens themselves to LF. Numbers are binary64. Only numeric
input fields may use the strings `NaN`, `Infinity`, `-Infinity` or `-0`; decode
those explicitly, never reinterpret ordinary text fields with the same content.

## How both app suites consume them

1. Resolve the repository root as the parent of `VOXCLIP_SHARED_DIR`, if set;
   otherwise walk up from `#filePath` (Swift) or `AppContext.BaseDirectory` (C#)
   until `shared/fixtures/llm` exists. Read files in place, not from app bundles.
2. Enumerate and sort every `*.json` here. Validate the envelope schema, file id,
   unique case ids and source hashes, then execute **every** case. Fail on an
   unknown `kind`; M2 cases may be explicitly reported as deferred until M2.
3. `format-transcript`: compare all line metadata and `rendered`. `to-fixed-1`
   and `format-time`: compare strings byte for byte. `to-fixed-random` expands
   the recipe below and compares each string with the stored expected list.
4. `finalize-clips`: expand `words` when it is a recipe, resolve the preset from
   the shared prompt, and compare the ordered result array exactly. `snap-pair`
   compares the two indices. `prepare-entries` compares all prepared entries;
   `string-helpers` trims and surrogate-safely truncates to `maxLength`.
5. `windows`: format the synthetic words, calculate the specified feature's
   budget, pack windows and compare all expected fields, including full absolute
   line labels. `choice` names the preset or strength. `pack-lines` supplies lines
   directly; an `error` expectation means the operation must fail with that code.
6. `tighten-verifier`: compare proposals and `rejectedCount`. `rejected` contains
   diagnostic `{editIndex, reason}` entries for the fixture harness, so rejection
   reasons can be tested without changing the app's public proposal contract.
7. `render-request`: load F1 from `format-transcript.json` (or use explicit
   `input.entries`), format the full entries, then select the inclusive
   `window.firstLine…lastLine` bounds when present. Render the chosen preset or
   strength with the given instructions. Compare `system`, `cachedBlock`,
   `instruction`, and the remaining canonical fields exactly. A gate expectation
   (`error`, `message`) makes no connector call. Use `input.connectorOptions`
   when comparing every `expected.connectors` entry.
8. `connector-request`: use `input.request`, connector and options directly.
   HTTP method, URL, header values and complete parsed JSON bodies must match;
   header names are case-insensitive. Compare prompt strings as UTF-8 bytes, not
   normalized Unicode. Per ai.md §4.1/§13.7 JSON object key order is not a wire
   requirement; arrays and values are. Both serializers must retain all fields
   and omit every unlisted one. The platform-specific `User-Agent` is deliberately
   excluded; test its `VoxClip/<version> (macOS|Windows)` value separately.
9. CLI output is `{executable, argv, stdin, cwd, files, …}`. Compare argv elements
   and stdin bytes, with no shell quoting or extra stdin newline. Substitute
   `<cwd>` and `<io>` with isolated sibling temporary directories before invoking
   a fake process. `files` specifies the exact compact UTF-8 schema file, without
   a trailing newline; the final-message output path is in argv. Flags/features
   in `options` model detected capabilities, not the host's installed CLI.
10. Apple output is a **logical** fresh-session request, not an HTTP body:
    compare instructions, prompt, recursively mapped schema, required properties,
    greedy options and output cap. On Windows validate the data/mapping as pure
    fixtures; do not instantiate Apple's unavailable framework.
    Schema names follow ai.md §6.7: root `<schemaName>`, property `N_P`, array
    item `N_P_item`, recursively. Nested objects and string enums use their full
    path names; primitive scalars have no schema names. Names must be unique
    within each schema so the SDK does not deduplicate an array item into a
    self-reference (`$ref: "#"`), which is forbidden. JSON property names and
    array budgets are unchanged. `GenerationSchema` JSON retains object names as
    byte-exact `title` values but omits string-enum names, so compare object
    titles with the logical fixture and derive enum builder names from their
    node paths rather than encoded JSON.
11. `voice-rewrite-request`: build a `VoiceRewriteRequest` from `input` (each
    source word is a `word` item), send it through the platform's
    `VoiceRewriteService` with a stub connector, and compare the sent
    `system`, `cachedBlock` and `instruction` as UTF-8 bytes, plus `feature`,
    `schemaName`, `schema`, `effort` and `language`. These cases have no
    connector renderings: the request travels the existing connector paths, and
    its `maxOutputTokens` depends on the connector and the source length.
    `expected.estimate` is the quote's estimate: `units` is `est()` (ai.md
    §11.5) of `system + cachedBlock + instruction`, `unit` is `token` and
    `basis` is `unknown`, with no price or credits. Compare it with the estimate
    of the quote the service prepares for the stub connector.
    `expected.preflight` is the ai.md §12.8 preflight for that stub connector,
    OpenAI, which has no output cap of its own: `sourceTokens`, the sent
    `maxOutputTokens`, `required` and `smallestContext`, the smallest context
    of at least 512 tokens with `required ≤ ⌊context × 0.9⌋`. Compare the sent
    `maxOutputTokens`, then send again through a stub that reports
    `smallestContext`, which must send, and one that reports one token less,
    which must fail with the context error before sending.
12. `patch-rewrite-request`: build a `PatchRewriteRequest` from `input` (its
    `entries` and one `ranges` item per formatted line), send it through the
    platform's `PatchRewriteService` with a stub connector that returns an
    empty `edits` list, and compare the sent request, the quote's estimate and
    the preflight as in step 11. The tag must be `patch-rewrite`.
13. `cli-reply`: run the platform's Claude Code connector with a fake process
    whose generation writes `input.stdout` as it is, with exit 0 and no stderr,
    for a `voiceRewrite` request with `input.model` and `input.schema`. Read
    the completion as a reply against that schema (ai.md §2.3). `expected` is
    either `rewrite` and the answering `model`, or `error`: `cliFailed` (stdout
    is no envelope), `truncated`, `refused` (with no category) or
    `invalidOutput`. Each platform's CLI connector suite replays these cases.

No fixture calls a provider or installed CLI. All auth values are `<key>` or
`Bearer <key>`. Runtime transport retries, process isolation/cleanup, auth
preflight, locale/tokenizer gates and response parsing remain the native apps'
stub tests from §13.7–§13.8; these goldens do not claim to exercise them.

## Synthetic inputs

- `U100`: indices 0…99, id/text `w{i}`, `start = i`, `end = i + 0.8`.
- `W1`: indices 0…19999, id `w{i}`, text `w{i}` plus `.` when `i % 15 == 14`,
  `start = 0.3 * i`, `end = 0.3 * i + 0.25`. Evaluate in that order in binary64,
  with no FMA. Expected window labels are the full transcript's labels.
- `lcg32-scaled-binary64-v1`: start with `state = seed`. For each sample,
  `state = (1664525 * state + 1013904223) mod 2^32`, using integer arithmetic;
  `x = (Double(state) / 4294967296) * scale`. Compare `toFixed1(x)` with the
  corresponding expected string. There are 100,000 stored oracle values, not
  100,000 separately duplicated case objects.

## Spec readings and underspecified edges

- **Small F1 / multiple windows:** normal F1 fits one production window. The
  rendering cases use explicit windows produced by a **test-only 66-entry packing
  limit**, with each preset's real overlap; do not change the production 8,000
  limit. W1 tests that real limit and the exact normative three-window bounds.
  Tighten's explicit F1 windows are consecutive and non-overlapping.
- **Custom without instructions:** §11.1's gate takes precedence over “every
  preset with/without instructions” in the parity paragraph. Its two cases expect
  `needInstructions`, not an invalid custom request.
- **Window overhead:** “longest window lines” means the longest UTF-8 formatted
  start/end times from the full lines, `k = 99`, and the longest possible topics
  continuation indices. W1's word-limit bounds are unchanged. The Apple W1 case
  uses the estimated budget; OS token-count shrink/retry needs native stubs.
- **Apple single-window array budget:** apply §11.5's `max(2, ceil(maxClips *
  1.5 / windowCount))` even for one window (8 for Best), while final selection
  still caps Best at 5. `maximumElements` is null for non-clip arrays.
- **Local models / CLI capabilities:** no local default model is catalogued.
  Inputs explicitly select synthetic `local-model` for LM Studio and `gemma4:12b`
  with a 32,768 context and completion/thinking capabilities for Ollama. These
  are fixture assumptions, not installation/availability claims. Default CLI
  cases support all catalog flags/features; separate variants remove them.
- **M1 cut-set prose:** the two M1 examples use independent cut sets, 0…10 and
  30…39 respectively, as implied by their stated 11/21 and 10/21 fractions.
- **Very large `toFixed1`:** editing §4.4 only expects durations below 2^52;
  ai.md §11.3 says all finite non-negative values match JS. At `x >= 1e21`, use
  JS's ordinary number string (exponent form), the `toFixed` early-return rule.
  Smaller inputs always use exact integer decomposition, never decimal/FMA.
- **Sentence-end `$` portability:** the ECMAScript regex from §11.3 does **not**
  match before a final line terminator without multiline mode. Some native regex
  engines differ; `literal-regex-terminal-newline` pins the JS behaviour.
- **Tighten whitespace / punctuation-only lines:** “Unicode whitespace” uses
  editing §4.5's explicit JS set, including FEFF but not U+0085. A line with no
  token-bearing entry has no neighbour for punctuation inheritance: empty keep
  cuts the line; a punctuation-only keep also normalizes to empty. Other cases
  inherit the specified preceding/following token entry's fate.
- **Anthropic custom-model schema fallback:** §6.1 does not specify the append
  separator. Use two LF characters before `Reply with only a JSON object…`,
  retaining the transcript block and the exact compact schema.

Change these choices only with a reviewed fixture diff and a matching spec
clarification. No goldens are hand-maintained.
